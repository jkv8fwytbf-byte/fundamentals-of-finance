# Plan v3: a private, outsourced Damodaran valuation system, built fast, explained slowly

Dated 2026-09-14. Replaces v2 after Siddharth's second review. Written for someone who is new to
all of this and alone: the first half is plain English, the technical appendix is at the end.
Every number was checked against a live vendor page or the files on disk on 2026-09-13/14.

## 1. What we are building, in one page

You want a machine that does what you used to do by hand in Damodaran's spreadsheet, for many
companies at once, in India and the US, with his own lecture corpus on tap, private to you, and
with nothing running on your Mac except an editor and the pi coding tool. Here is the whole thing
in four sentences:

1. **A calculator.** A program that takes a company's numbers (revenue, operating income, debt,
   cash, shares) plus Damodaran's reference tables (industry betas, country risk premiums, the
   risk-free rate) and computes value per share exactly the way his spreadsheet does. We know it
   is exact because his spreadsheet ships with a worked example (Almarai, a Saudi food company,
   value 7.187840270062114 per share) and our program must reproduce that number to six decimals
   before it is allowed to value anything else. That is the "golden test".
2. **A database in the cloud (Neon).** Every number the calculator uses is stored with three
   labels: where it came from (source), whether you are allowed to show it to others (licence),
   and which snapshot of Damodaran's data it belongs to (vintage; he updates his tables every
   January, with quarterly and monthly refreshes of two of them, so one year has several
   versions of the risk-free rate and the risk premium and they must never be mixed). The
   database refuses to save a number that is missing any of the three labels.
3. **A librarian in the cloud (Pinecone + Voyage).** His 609 blog posts, lecture packets, book,
   datasets and transcripts are cut into ~60,000 passages, each turned into a vector so a
   question can find the right passages. When you ask "why is terminal growth capped at the
   risk-free rate?", the model answers only from the passages it was handed and cites them.
4. **Robots that run at night (GitHub Actions).** Scheduled jobs pull new filings from SEC
   EDGAR (US, free, public domain) and later from EODHD (India, paid), re-value your watchlist,
   check whether Damodaran posted a new risk-premium file, and write everything to the database.

Your interface is **pi**: you type "value Trent" or "ask Damodaran why he strips the default
spread out of the Indian risk-free rate" and the tools answer, with the vintage and the sources
printed every time. Reports come out as PDF. There is no website in v1 because you do not want
one; if anyone else ever uses it, a website goes in front of the same database later.

### M2 — Foundation build (me; days 3–7; you read the walkthrough)
1. Private repo `valuation` inside a free GitHub organisation (TypeScript, pnpm workspace) with
   `AGENTS.md` (the eight hard rules), `.pi/` (sandbox policy, skills, prompt templates), and CI
   on GitHub's own Linux runners: 2,000 free minutes/month, then $0.006/min; a hard Actions
   spending limit of $25; `timeout-minutes` on every job; schedules off the hour (`17 6 * * *`)
   because top-of-hour cron runs get dropped under load; a `last_run_at` row in Neon with a
   staleness alarm. Switch to Blacksmith (3,000 free minutes, ~2× faster, $0.004/min) only if
   usage passes ~3,000 minutes/month.
2. The calculator (`packages/engine`): a formula-by-formula port of the spreadsheet; the golden
   fixture extracted from the workbook by script (never typed); the golden test required in CI;
   diagnostics turned into real errors and warnings.
3. The database (`packages/db`, Neon): the tables from §9; the constraints proven ("insert a
   number without a vintage → refused"); the Damodaran datasets loaded once by an Actions job with
   their vintage taken from each file's own "Updated" cell; the three 2026 market vintages seeded.
4. US ingest: SEC EDGAR for Apple, Costco and three more US names of your choice; the LTM rule;
   Apple's missing interest-expense line shown as a visible flag, not a silent zero.
5. The librarian (`packages/rag`): tier 1 (blog posts) and tier 3 (dataset sentences) indexed in
   Pinecone with Voyage; the grounded prompt; both smoke questions passing; the exam-based eval
   set built.
6. pi tools: `value_company`, `get_industry_stats`, `search_corpus`, `report` (markdown + PDF via
   a job); prompt templates `/ship`, `/golden`, `/vintage`; skills for the valuation rules, the
   India rules and the corpus.
7. Nightly jobs: EDGAR refresh on new filings, watchlist revaluation, monthly ERP / quarterly
   CRP watch that opens a GitHub issue when Damodaran posts a new file.
8. `docs/walkthrough.md`: every folder and file explained; how to run each command; what to try first.
**Done when:** `pi` → `value_company AAPL US` prints value/share, WACC, rating basis, vintage and
licence; `search_corpus` answers the smoke questions with citations; the golden test is green in
CI and a deliberate lag change turns it red; the nightly job has run once.

## 8. Bloomberg, OCR, crawling, sub-agents, speed and cost per task

- **Bloomberg API library: verdict.** The page you found is the download index for Bloomberg's
  BLPAPI SDK (v3.26.8.1). The SDK is free to download and connects to nothing without an
  entitlement. The page itself says the Linux/macOS builds "are only compatible with the Bloomberg
  Server API and B-Pipe"; Windows builds ride a logged-in Terminal (~$32k/year, 2-year minimum).
  Server API, B-PIPE and Data License are enterprise contracts with no list price. **A
  bloomberg.com Digital or All Access subscription is a reading product with no data entitlement,
  no developer portal and no consumer API in 2026.** What Bloomberg does expose for free:
  undocumented headline-only RSS feeds (`feeds.bloomberg.com/markets/news.rss`, `technology`,
  `economics`, `industries`, `bview`, verified live 2026-09-14; no article text, they rot without
  notice) and email newsletters. So: Bloomberg India stays a reading source. Your notes go into
  `narrative_note` with URL + date + your own one-sentence paraphrase and the named input they
  move; never article text, never in the librarian's index (a database rule enforces this). The
  RSS headlines can feed a "did anything happen" signal later; fundamentals come from EDGAR,
  Damodaran's tables and EODHD.
- **OCR.** Turning a picture of a page into text. Three of Damodaran's "Dark Side" decks are
  image-only; check with `pdffonts` first, then use Mistral Document AI 4.1 through the batch
  endpoint ($2 per 1,000 pages; the three decks cost about a dollar). Verify with an arithmetic
  round-trip: if a table's columns do not sum to its total, the OCR is wrong.
- **Web crawling vs search APIs vs scraping.** Search = ask a question, get ranked pages; crawl
  = walk a whole site; scrape = pull fields off one page. You mostly need none of it: SEC EDGAR
  has official free JSON APIs and Damodaran's pages are static files. Terms of service, not the
  law, are the real risk (the hiQ v. LinkedIn precedent), so honour `robots.txt` and stamp a
  licence class on every row. If you add news discovery: Parallel or Exa (free tiers), never
  screener.in/Tickertape.
- **Sub-agents.** A helper session pi spawns with its own context and a narrower tool set; it
  returns a summary. Good for parallel reading of ten filings; bad for anything whose numbers you
  must audit (make helpers write rows to Neon and return ids, not prose). Costs roughly N× the
  tokens. `pi-subagents` (install with `pi install npm:@tintinweb/pi-subagents`) adds this to pi;
  turn on `showCost` and `reportUsage` immediately. Deferred to M5.
- **Speed and cost per task, and what the Artificial Analysis columns mean.** Intelligence Index
  = a weighted exam across 10 tests; Coding Agent Index = harness + model pairs on real coding
  tasks; AA-Omniscience = does it make things up (the metric that matters for a citation-bearing
  chat); tokens per second = typing speed after the first token; time to first token = the wait
  before it starts (for reasoning models, the first *thinking* token); cost per task = the dollars
  to finish one exam question, the number that maps to your bill; blended price assumes a 7:2:1
  cache:input:output mix you may not achieve. Traps: reasoning tokens bill as output, the same
  model is served by many providers at different prices and quantisations, and the leaderboard
  row is often not the endpoint you get routed to. Pick per job, not by headline.
- **Fine-tuning, at three levels** (doc B ch. 2 and 9): (1) the harness, which is what you will
  actually do: `AGENTS.md`, skills, extensions, prompt templates, sandbox, model routing; costs $0
  and is 95% of the quality; (2) prompt and context engineering; (3) the model, as an outsourced
  service (Together, Fireworks, Vertex, Unsloth on Colab): ~$2 per training run for 800 examples
  on a ≤16B model, but it changes form, not facts, needs 500–1,000 hand-corrected examples, and a
  dedicated GPU endpoint left running can eat $200 in a weekend. Not in v1; revisit when you have
  500+ logged corrections and a repeated formatting failure.

## 9. Technical appendix (skip on first read)

### 9.1 Correctness rules in plain words
- **Golden test.** The spreadsheet's own example must reproduce to 1e-6 (0.000001) before any code
  merges. The expected values are extracted from the workbook by a script, and the file holding
  them cannot be edited by pi (sandbox rule) so the agent can never "fix" the test instead of the code.
- **Vintage.** Every run stores three ids: which market file (risk-free rate, mature ERP), which
  country-risk file, which industry file. The 2026 data alone carries risk-free rates of 3.95%,
  4.58% and 4.75% and ERPs of 4.20%, 4.23% and 4.46%; mixing them silently is the most common way
  to get a confidently wrong value.
- **Source and licence class.** Every stored fact says where it came from and one of:
  `public_domain` (SEC), `damodaran_public` (his tables, free for research with attribution),
  `open_access` (RBI, arXiv, SSRN author copies), `asr_youtube` (auto-captions),
  `licensed_personal` (EODHD, only for you), `proprietary_personal` (Bloomberg notes, only for you),
  `link_only` (books, paid newsletters: we store the link, never the text). The librarian's index
  has a database rule that refuses the last three. That rule is what lets you go public later
  without an audit.
- **India rules.** Risk-free = RBI 10-year G-sec yield minus India's default spread (Damodaran's
  local-currency rule; otherwise sovereign risk is counted twice because the cost of debt already
  adds it). ERP = mature ERP + India CRP (Jan-2026: 4.23% + 2.85% = 7.08%). If an India industry
  has fewer than 10 firms (27 of 94 do), use the emerging-markets table, then Global, and print
  which one was used.
- **No advice.** A test scans every report and every chat answer for buy/sell/hold/target price.

### 9.2 Engine (TypeScript, pure functions, float64)
Modules mirror the sheets: `rating.ts` (synthetic rating from interest coverage, three firm-type
tables, country default spread), `costOfCapital.ts` (four approaches; industry-average and
distribution approaches add `rf − table.embedded_rf`, stored per table: 4.58% workbook, 3.95%
wacc.xls), `fcff.ts`/`terminal.ts` (growth path, margin convergence, tax fade, reinvestment =
ΔRevenue ÷ sales-to-capital with the lag switch, NOL, running-product discount factors, terminal
WACC = rf + mature ERP, terminal reinvestment g/ROIC), `failure.ts`, `options.ts` (disabled for
Almarai), `india.ts`, `reverseDcf.ts`, `monteCarlo.ts`. Output carries the full audit (rating
basis, interest missing, tier used, three vintage ids, sources, engine version, input hash).
Excel and JavaScript share IEEE-754 float64, so an order-faithful port agrees to ~1e-12.

### 9.3 Database (Neon) tables
`vintage` (kind market/crp/industry/ltm/corpus, as_of, label, source_url, sha256, license_class),
`country_risk`, `industry_stat` (long format: one row per region × industry × metric, with
n_firms), `company`, `fact` (source_url, license_class, filed, accession, vintage_id all NOT NULL),
`ltm_financials` (interest_missing flag), `valuation_run` (inputs, inputs_sha256, outputs, three
vintage ids NOT NULL, industry_tier_used, rating_basis, seed, story_kind), `watchlist`,
`narrative_note`, `chunk_manifest` (with the licence CHECK), `rag_eval_case`, `rag_eval_run`,
`realised_price`. Raw source bytes (the zips, the workbook, the markdown corpus, OCR output)
live in a private Cloudflare R2 bucket keyed by sha256 (free, zero egress); the database row
stores the key and hash.

### 9.4 Librarian (Pinecone + Voyage) and models
Pinecone serverless index, 1024-dim vectors from Voyage `voyage-context-4`, Voyage `rerank-3`
from 50 candidates to 8; metadata `{source_url, title, date, doc_type, license_class, vintage, asr,
region, company}`; namespaces per source type. Tiers: 1 blog posts → 2 book, packets (pptx with
speaker notes), exams → 3 dataset rows as sentences → 4 transcripts after a $11 punctuation pass.
Never indexed: third-party press in the crawl, filings, the Tykoh spreadsheet guide, Bloomberg,
EODHD. Hybrid router: single-document questions stuff the document; corpus-wide questions retrieve.
RAG is required (30 M tokens vs a 2 M largest window) and costs ~$0.0143 per question on GLM-5.3.
Models pinned in one file with the Artificial Analysis index version: `z-ai/glm-5.3` (pi default,
answers; AA Intelligence Index v4.3 = 45, best open weight; $1.40/$4.40 per M tokens, cache read
$0.26), `z-ai/glm-5.3-flash:batch` (bulk, $0.075/$0.25, reasoning off), `moonshotai/kimi-k3`
(judge; best open-weight calibration), `deepseek/deepseek-v4.1-flash` (fallback). Never DeepSeek
V4 Pro (94% hallucination rate). Doc A explains every column of this table.
