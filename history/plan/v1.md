# Plan: Damodaran-style valuation platform for Indian + global equities — where to start

## Context

Siddharth wants a long-horizon (no intraday/day-trading) system that automates Aswath Damodaran's
valuation approach (intrinsic DCF, cost of capital with country risk premium for India, relative
pricing) across many companies and sectors, so a diversified watchlist can be valued from
fundamentals instead of hand-filling one Excel model at a time. Everything public from Damodaran
(site crawl, blog, lecture packets, spreadsheets, datasets, YouTube transcripts, the book) has been
collected into `~/Downloads` and mirrored to Markdown. A separate cloud session sketched a UI:
company picker → backend (fetch prices & filings, Damodaran-style models) → valuation tabs +
an "Ask Damodaran" chat grounded in the corpus.

Siddharth is new to the software-tooling side (MCP, CI/CD, PRs, GitHub Actions, worktrees,
sandboxes, Linear, Figma, Vercel, OpenRouter, pi.dev vs OpenCode, fine-tuning) and wants to
**learn as he builds**, prefer **managed third-party services over running things himself**, and
design for **scale** without over-building. He also wants an honest way to find out "how wrong
Damodaran is", so the system must be evaluable, not just a calculator.

This plan gives: what exists (verified), the recommended architecture, seven milestones (each
teaching exactly one tool), the vocabulary explained, and the assumptions that need his answer.

## Engine design essentials

- Frozen dataclasses mirror sheet cells (cell refs in docstrings): `Financials` (LTM + prior 10-K),
  `CompanyInputs`, `Levers` (`None` = ginzu initialiser, resolved once into `ResolvedLevers` with
  `origin`), `Overrides` (the nine default blocks), `CostOfCapitalChoices` (approach; beta method;
  ERP method; `cod_approach` direct|synthetic|actual; firm_type; rating; maturity), `Options`,
  `Reference` (tables per region, countries, regions, statdist, rating tables, mature_erp, per-table
  `embedded_rf`, vintage).
- Pure functions over numpy arrays of shape `(n,)`: n=1 is the point estimate, n=10,000 is Monte
  Carlo; the pandas table is only a presentation view. Chain: `costofcapital.compute()` →
  `rating.synthetic()` → `projection.build()` → `terminal.value()` → `bridge.equity()` →
  `options.solve()` (fixed point, raises on non-convergence) → `diagnostics.check()`.
- The industry-average and distribution approaches add `(rf − table.embedded_rf)`: 4.58% for ginzu
  tables, 3.95% for `damodaran_2026-01` tables, never a literal.
- Diagnostics. Hard errors: WACC_T ≤ g_T; no industry row after the fallback walk; missing interest
  expense with synthetic rating; currency mismatch inputs↔rf; unit sanity; vintage mixing under
  strict policy; option loop non-convergence. Warnings: the sheet's six diagnostics with fix-it
  text; g_T > rf + 0.5pp; **terminal WACC drops the CRP** (prints the pp step-down from year-10
  WACC, material for India); effective tax outside [0, marginal]; negative reinvestment; CRP vintage
  > 6 months; industry table > 12 months; rf older than 31 days; fallback used; `personal_use_only`
  input present.
- Vintage policy (ADR 0001): industry tables, CRP row and mature ERP come from the **same January
  drop** by default (`2026-01`); `--crp 2026-07` flips the CRP row and mature ERP together and prints
  WARN; a monthly `ERP*.xlsx` never sets mature ERP; rf is an as-of market input; printed on page 1
  and stored in `runs.vintage_json`.

## Vocabulary you asked about (plain English, current as of Sept 2026)

- **Harness.** The scaffolding around a model: what goes into the prompt, which tools it can call,
  the loop of "call model → run tool → feed result back", permissions, and the UI. The model is the
  engine; the harness is the car. Claude Code, OpenCode and pi are all harnesses. "Fine-tuning the
  harness" just means shaping that scaffolding (CLAUDE.md, skills, MCP servers, subagents, output
  schemas, evals). Costs only your time and is reversible in seconds. That is 90% of the value here.
- **Claude Code vs OpenCode vs pi.dev.** Claude Code: Anthropic's closed harness, Anthropic models
  only, built-in permission prompts, MCP, skills, hooks. You already pay for it; stay on it.
  OpenCode (opencode.ai, MIT): free, 75+ model providers, plan-then-build review gate; a good free
  secondary for bulk grunt work with a cheap model. pi (pi.dev, MIT, by Mario Zechner): a
  deliberately minimal harness (~4 tools) that you extend in TypeScript; it has **no built-in
  permission system**, you are expected to sandbox it yourself. It is a project, not a tool. Skip it
  for now. Note: third-party harnesses using your Claude subscription draw from a separate, capped
  "Agent SDK" pool ($200/month on Max 20x), not your interactive quota.
- **OpenRouter.** One API key and one bill in front of hundreds of models. Per-token prices are
  pass-through, plus a 5.5% fee on credit purchases. Useful when you want to A/B cheap models or run
  a bulk job (punctuating 1,400 transcripts) without signing up with five vendors. Not needed for the
  main reasoning; call Anthropic directly for that.
- **Fine-tuned open-weight model.** Taking a downloadable model (Llama, Qwen, Mistral) and training
  a small adapter (LoRA) on your own examples so its *behaviour* changes. Compute is cheap (a
  published finance fine-tune cost about $15 of GPU). But it is for **form, not facts**: Damodaran's
  method is facts plus arithmetic plus tables that change every January. That is a retrieval +
  deterministic-code problem. Revisit only after you have logged 1,000+ real corrections and hit a
  formatting failure that prompting cannot fix.
- **Artificial Analysis.** Independent benchmarks of models and providers on intelligence, speed
  and price. The screenshot you pasted is their **Search Index** (launched 2026-08-18): it ranks
  *web-search APIs* (Parallel, Exa, Firecrawl, Tavily, Brave...) by how much they lift the same model
  on research tasks. Relevant only if you later add a news/qualitative layer. The main index is useful
  to pick the cheapest model that clears your quality bar for bulk jobs.
- **Vector store: Pinecone vs Postgres + pgvector.** Your corpus is ~60k chunks; pgvector handles
  that in milliseconds and lets you `JOIN` semantic hits against your fundamentals tables in one SQL
  query. Pinecone only wins at ~50–100M vectors. Pinecone Assistant (what the old harness targeted)
  is a black box over chunking and citations. Use Postgres + pgvector (Neon free tier, scale-to-zero,
  no Docker needed) or a local file index (sqlite-vec / LanceDB) for v0.
- **MCP (Model Context Protocol).** An open standard (now under the Linux Foundation) for plugging
  tools into Claude Code and other agents: "USB-C for AI tools". A server exposes tools; Claude calls
  them. Ready-made servers exist for SEC EDGAR (EdgarTools, free, no key) and Indian markets
  (FinStack). Writing your own over your valuation engine is ~50 lines with FastMCP and is the single
  highest-leverage extension move you can make.
- **Git branch / PR (pull request).** A branch is a parallel line of history; a PR is the request to
  merge it, with a diff, review comments and automated checks. You will make one per milestone.
- **CI/CD and GitHub Actions.** CI = every PR automatically runs your tests; CD = a green main
  branch auto-deploys. GitHub Actions is GitHub's built-in runner for this, configured by one YAML
  file in `.github/workflows/`. Free for public repos and generous for private ones.
- **Worktree.** A second checkout of the same repo in another folder, so two branches can be worked
  on at once (for example, Claude Code refactoring the engine while you edit docs). `git worktree add`.
- **Sandbox / permissions.** Running code where it cannot touch things it should not (your keys,
  your home folder, the network). Claude Code's permission prompts are the beginner version; Docker
  or a cloud sandbox is the strong version. Docker is not installed on this Mac and is not required
  for v1.
- **Secrets.** API keys live in a `.env` file that is listed in `.gitignore`, loaded by the app at
  start, and never pasted into code or chat. Right now you have zero keys anywhere, which is the
  correct starting state.
- **Linear.** An issue tracker (like a to-do list for software with statuses, priorities and
  links to PRs). Optional for a solo builder; GitHub Issues does the same job for free. Add Linear
  only if you like its UI.
- **Figma.** Design tool for mocking screens before coding them. Useful the week you build the UI,
  not before. The Figma MCP is available in this app for design-to-code when that week comes.
- **Vercel.** Hosting for the Next.js front end (and Python functions). Hobby plan is free but
  **non-commercial only**; cron jobs run at most once a day. Fine for a personal EOD tool.
- **Scalability ("capitalization").** For this project it means three things: (1) adding a company,
  sector, region or data vendor is a data change, not a code change; (2) every number carries its
  source, licence class, fetch time and vintage so you can swap sources without silent drift;
  (3) compute that grows with the universe (ingest, embeddings, batch valuations) runs as scheduled
  jobs on managed services, not on your laptop.
- **Shorting.** Borrowing shares to sell now and buy back later, profiting if the price falls. It
  has unlimited theoretical loss and borrow costs, and in India single-stock shorting is done via
  futures/options with lot sizes and expiries. Out of scope for v1. The platform can still *flag*
  "price far above value" names; acting on that is a separate, later decision.
