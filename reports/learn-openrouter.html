THE BIG PICTURE
One door in front of every model

An AI model is a program running on some company's servers. You do not download it; you talk to it over the internet. You send text, you get text back. The door you send it through is called an API: a web address that accepts a request written in an agreed format and returns a response in an agreed format.

The problem. Every company has its own door. OpenAI, Anthropic, Google, Meta, Mistral, DeepSeek — each has its own account, its own billing, its own API key, its own request format and its own quirks. Want to try a different model? New account, new key, new code. And the same model is often hosted by several different companies (called providers) at different prices and speeds.

What OpenRouter does. It puts one door in front of all of them. One account, one key, one web address, one request format. You switch models by changing a single word in your request. Behind the door, OpenRouter picks which provider serves your request (it prefers the cheap, reliable ones), falls back to another if one is down, and sends you one bill.

Why people use it (from OpenRouter's own principles page): the future is multi-model and multi-provider; one standard format means switching models needs no code change; one bill; higher availability through fallbacks; and they scout prices and speeds across providers so you don't have to.

Why this matters for the tool we build

We write the calling code once, today. From then on, which model answers is a decision, not a rewrite. That single fact is what makes the cost chapter possible: cheap model for easy steps, expensive model only where it earns its price.

CONCEPT 1
Your first call, field by field

Every call to OpenRouter has three parts. Where: the web address, always https://openrouter.ai/api/v1/chat/completions, no matter which model. Who: a header line Authorization: Bearer <your key> — "Bearer" just means "the holder of this key". What: a small JSON document saying which model, the conversation so far, and any limits.

"The conversation so far" is a list of messages, each with a role. system is standing instructions ("you are a concise research assistant"); user is you; assistant is the model's earlier replies, if any. The model reads the whole list every time — it has no memory between calls except what you send.

The code

brief/ask.pypython
"""Lesson 1 - one raw HTTP call to OpenRouter. No SDK, every field visible.

Usage:
    uv run brief/ask.py                      # cheap default model
    uv run brief/ask.py anthropic/claude-haiku-4.5   # same code, different brain
    uv run brief/ask.py --raw                # also dump the full JSON that came back
"""

import json
import os
import sys

import requests
from dotenv import load_dotenv

load_dotenv()  # reads .env in this folder so OPENROUTER_API_KEY becomes available
API_KEY = os.environ["OPENROUTER_API_KEY"]

# Picked from the live catalog today: $0.019 in / $0.03 out per million tokens.
DEFAULT_MODEL = "mistralai/mistral-nemo"

args = [a for a in sys.argv[1:] if not a.startswith("--")]
model = args[0] if args else DEFAULT_MODEL
show_raw = "--raw" in sys.argv

response = requests.post(
    "https://openrouter.ai/api/v1/chat/completions",  # the ONE endpoint for every model
    headers={
        "Authorization": f"Bearer {API_KEY}",          # who is paying
        "Content-Type": "application/json",
    },
    json={
        "model": model,                                 # which brain to use
        "messages": [                                   # the conversation so far
            {"role": "system", "content": "You are a concise research assistant."},
            {"role": "user", "content": "Explain what an API is in two sentences, for a complete beginner."},
        ],
        "max_tokens": 200,                              # cap on how long the answer may be
    },
    timeout=60,
)

data = response.json()
if "error" in data:                                     # an HTTP 200 can still carry an error body
    raise SystemExit(f"OpenRouter error: {data['error']}")

print(data["choices"][0]["message"]["content"])
print("---")
print("served by:", data["model"])                      # the model that actually answered (and was billed)
usage = data["usage"]
print(f"tokens:    {usage['prompt_tokens']} in / {usage['completion_tokens']} out")
print(f"cost:      ${usage['cost']:.6f}")

if show_raw:
    print("\n=== full response JSON ===")
    print(json.dumps(data, indent=2))

Fallback lists and "latest" aliases

Two routing features you get for free. A fallback list: instead of "model", send "models": [first, second, …] and OpenRouter tries the next one if the first fails (rate-limited, down, rejected, too long). An alias like ~anthropic/claude-haiku-latest always points at the newest model in that family, so your code never goes stale — the response's model field tells you what it resolved to.

brief/fallback.pypython
"""Lesson 1b - fallbacks and aliases: let OpenRouter pick when your first choice fails.

Usage:
    uv run brief/fallback.py
"""

import os

import requests
from dotenv import load_dotenv

load_dotenv()
API_KEY = os.environ["OPENROUTER_API_KEY"]
URL = "https://openrouter.ai/api/v1/chat/completions"
HEADERS = {"Authorization": f"Bearer {API_KEY}", "Content-Type": "application/json"}
QUESTION = [{"role": "user", "content": "Name one thing to check before trusting an AI's answer. One sentence."}]


def call(body: dict) -> None:
    data = requests.post(URL, headers=HEADERS, json=body | {"messages": QUESTION, "max_tokens": 80}, timeout=60).json()
    if "error" in data:
        print("  ERROR:", data["error"]["message"])
        return
    print("  answer:   ", data["choices"][0]["message"]["content"].strip())
    print("  served by:", data["model"], "| cost: $%.6f" % data["usage"]["cost"])


print("1) A fallback list: the first model here does not exist, so OpenRouter should move on to the second.")
call({"models": ["mistralai/mistral-nemo:free", "mistralai/mistral-nemo"]})

print("\n2) An alias: ~anthropic/claude-haiku-latest always points at the newest Haiku.")
call({"model": "~anthropic/claude-haiku-latest"})

Gotcha · the response's model is the source of truth

With fallbacks, aliases, or the auto-router, the model that answers may not be the one you named. You are billed for the one in the response. Log it. And ~latest aliases can silently jump to a new version — for anything you need to reproduce exactly, pin a concrete name like anthropic/claude-haiku-4.5.

How routing works at a high level (details in chapter 6): among providers that have not had an outage in the last 30 seconds, OpenRouter picks one weighted by the inverse square of its price — a provider charging $1 per million is 9× more likely to be tried first than one charging $3 — and keeps the rest as fallbacks. Suffixes change that: :floor sorts providers by price and :nitro by throughput (tokens per second). :free is different in kind: it selects the model's separate free-tier entry, with its own price, context window and rate limits — and if the model has no free entry the request errors rather than quietly using the paid one, which is exactly why run 1 above needed the fallback list.

CONCEPT 2
The catalog, the parameters, and the errors

Before you can pick a model you need to see the menu. GET https://openrouter.ai/api/v1/models returns every text-producing model with its price, context size and abilities (add ?output_modalities=all to also see image, audio and embedding models). It is public — no key, no cost — so it is also a nice way to see what an API response looks like before spending anything.

Gotcha · prices are per token, as strings

The catalog says "prompt": "0.000000019". That is dollars per single token. Everyone talks in dollars per million tokens, so multiply by 1,000,000: $0.019. The script below does this in per_million(). Two prices always matter: prompt (what you send in) and completion (what comes back), and completion is usually 2–5× dearer.

A model-discovery utility

brief/models.pypython
"""Lesson 2 - the model catalog. GET /api/v1/models is public: no key, no cost.

Usage:
    uv run brief/models.py                 # cheapest tool-capable models + a few flagships
    uv run brief/models.py openai/gpt-5-mini   # show one model's full record
"""

import json
import sys

import requests

CATALOG_URL = "https://openrouter.ai/api/v1/models"


def per_million(price_per_token: str) -> float:
    """OpenRouter prices are strings in USD *per token*. Humans think per million."""
    return float(price_per_token) * 1_000_000


def load_catalog() -> list[dict]:
    return requests.get(CATALOG_URL, timeout=30).json()["data"]


def is_plain_paid_chat_model(m: dict) -> bool:
    """Skip :free / :batch variants and ~latest aliases; keep text models that support tools."""
    return (
        not m["id"].endswith((":free", ":batch"))
        and not m["id"].startswith("~")
        and "text" in m["architecture"]["output_modalities"]
        and "tools" in m["supported_parameters"]
        and float(m["pricing"]["prompt"]) > 0
    )


def row(m: dict) -> str:
    caps = "tools" + (", json-schema" if "structured_outputs" in m["supported_parameters"] else "")
    return (f"{m['id']:<42} in ${per_million(m['pricing']['prompt']):>7.3f}  "
            f"out ${per_million(m['pricing']['completion']):>8.3f}  "
            f"ctx {m['context_length']:>9,}  {caps}")


if __name__ == "__main__":
    catalog = load_catalog()

    if len(sys.argv) > 1:                       # one model, full record
        wanted = sys.argv[1]
        match = next((m for m in catalog if m["id"] == wanted), None)
        print(json.dumps(match, indent=2) if match else f"{wanted} not found")
        sys.exit()

    print(f"{len(catalog)} models in the catalog right now\n")
    usable = [m for m in catalog if is_plain_paid_chat_model(m)]
    usable.sort(key=lambda m: per_million(m["pricing"]["prompt"]) + per_million(m["pricing"]["completion"]))

    print("10 cheapest models that support tool calling (price per MILLION tokens):")
    for m in usable[:10]:
        print("  " + row(m))

    flagships = ["openai/gpt-5-mini", "anthropic/claude-haiku-4.5", "google/gemini-2.5-flash",
                 "anthropic/claude-sonnet-5", "anthropic/claude-fable-5.1", "openai/gpt-5.5"]
    print("\nA few well-known ones for scale:")
    for m in catalog:
        if m["id"] in flagships:
            print("  " + row(m))

    free = [m["id"] for m in catalog if m["id"].endswith(":free")]
    print(f"\n{len(free)} free variants exist (rate-limited), e.g. {', '.join(free[:3])}")

The parameters that matter

Beyond model and messages, three settings cover most needs. temperature (0 to 2) controls randomness: 0 is as repeatable as it gets, 1 is the usual default, 2 is chaos. max_tokens caps how long the answer may be — which also caps how much you can be charged. top_p is another randomness dial; leave it alone unless you know why. A sampling setting a model does not support (say top_k on a model that lacks it) is silently dropped, not rejected — check supported_parameters if it matters. Reasoning settings are the one exception: a value the model cannot honour can be rejected outright.

Usage:
    uv run brief/params_and_errors.py
"""

import os

import requests
from dotenv import load_dotenv

load_dotenv()
API_KEY = os.environ["OPENROUTER_API_KEY"]
URL = "https://openrouter.ai/api/v1/chat/completions"
MODEL = "mistralai/mistral-nemo"


def ask(body: dict, key: str = API_KEY) -> None:
    r = requests.post(URL, headers={"Authorization": f"Bearer {key}"}, json={"model": MODEL} | body, timeout=60)
    data = r.json()
    if "error" in data:                                   # always check the body, not just r.status_code
        e = data["error"]
        print(f"  HTTP {r.status_code} | error code {e['code']} | {e['message']}")
        if e.get("metadata"):
            print(f"  metadata: {e['metadata']}")
        return
    c = data["choices"][0]
    print(f"  finish_reason={c['finish_reason']!r} | {data['usage']['completion_tokens']} tokens out | "
          f"{c['message']['content'].strip()!r}")


prompt = [{"role": "user", "content": "Give me a name for a coffee shop. Just the name."}]

print("temperature=0 (as predictable as it gets) - asked twice:")
ask({"messages": prompt, "temperature": 0, "max_tokens": 20})
ask({"messages": prompt, "temperature": 0, "max_tokens": 20})

Gotcha · hidden "thinking" tokens count against max_tokens

Some models reason privately before answering (the catalog marks these; openai/gpt-5-mini reasons mandatorily). Those reasoning tokens are billed and count against your max_tokens. Set a small cap and you can get finish_reason: "length" with an empty answer — the budget was spent thinking. Chapter 6's benchmark hit exactly this. Fix: raise max_tokens, or cap the thinking with a lower effort such as "reasoning": {"effort": "low"} (or "minimal"). Only models whose catalog entry says reasoning.mandatory: false accept "effort": "none" — gpt-5-mini is mandatory and rejects it.

Errors

An error comes back as {"error": {"code": …, "message": …}}. The two you hit above: 401 — the key is wrong ("User not found"); 400 — the request is malformed, here a model name that does not exist. The rest of the table:

CodeMeaningWhat to do

Gotcha · HTTP 200 does not mean success

Once the provider starts answering, OpenRouter has already sent "200 OK". If the provider then fails, the error arrives inside the body: as a top-level error field with no choices at all, or — when some output had already been produced — inside choices[0] with finish_reason: "error". Every script in this guide checks if "error" in data rather than trusting the status code; a production version should also check finish_reason. When streaming (chapter 4) this matters even more.

CONCEPT 3
Three ways to make the same call

So far we used requests, the general-purpose Python HTTP library: you write the URL, the headers and the JSON yourself. That is the honest way to learn, and it never hides anything. Real projects usually use a SDK, a library that wraps the API in ordinary functions. Two are relevant for Python:

  • The OpenAI library, pointed at OpenRouter. Because OpenRouter speaks the same format as OpenAI's API, you can use OpenAI's own openai package and change two lines: the base URL and the key. Huge amounts of existing code and tutorials work unchanged. OpenRouter-only fields (like the models fallback list or provider rules) go in extra_body.
  • The official openrouter package. Generated from OpenRouter's own API description, so every OpenRouter feature is a named argument and new features appear as soon as they ship. Also covers non-chat things: listing models, checking credits, managing keys.

CONCEPT 4
Streaming, and answers in a fixed shape

Streaming: show words as they are written

A normal call waits until the whole answer exists, then delivers it. For a 300-word answer that can be five silent seconds. Streaming sends each little piece as soon as it is generated — the effect every chat app has. Total time barely changes; the felt wait collapses to the time-to-first-word. In the run below the first word arrived after 0.64 s and the whole answer after 2.14 s.

Mechanically: add "stream": true, and instead of one JSON document you receive a long-lived connection that sends lines beginning with data: , each holding a tiny JSON "chunk" with a few characters in choices[0].delta.content. The stream ends with the literal line data: [DONE]. Just before that, one last chunk carries the usage and cost.

def stream_by_hand() -> None:
    """Server-Sent Events: the server keeps the connection open and sends 'data: {...}' lines."""
    started = time.time()
    first_token_at = None
    first_line = last_line = None
    usage = None
    with requests.post(
        "https://openrouter.ai/api/v1/chat/completions",
        headers={"Authorization": f"Bearer {API_KEY}"},
        json={"model": MODEL, "messages": MESSAGES, "max_tokens": 120, "stream": True},
        stream=True,
        timeout=60,
    ) as r:
        for line in r.iter_lines(decode_unicode=True):
            if not line:
                continue                      # blank lines separate events
            if line.startswith(":"):
                continue                      # keep-alive comment, e.g. ': OPENROUTER PROCESSING'
            if not line.startswith("data: "):
                continue
            payload = line[len("data: "):]
            if payload == "[DONE]":
                break                         # literal end marker, not JSON
            first_line = first_line or line
            last_line = line
            chunk = json.loads(payload)
            if "error" in chunk:
                raise SystemExit(f"stream error: {chunk['error']}")
            if chunk.get("usage"):
                usage = chunk["usage"]        # the final accounting chunk arrives just before [DONE]
            delta = chunk["choices"][0]["delta"].get("content") if chunk["choices"] else None
            if delta:
                if first_token_at is None:
                    first_token_at = time.time()
                print(delta, end="", flush=True)
    print(f"\n\n  first token after {first_token_at - started:.2f}s, finished after {time.time() - started:.2f}s")
    print(f"  usage from the last chunk: {usage['prompt_tokens']} in / {usage['completion_tokens']} out, cost ${usage['cost']:.6f}")
    print("\n  what the FIRST line on the wire looked like:\n   ", first_line)
    print("\n  what the LAST data line looked like (the accounting chunk):\n   ", last_line)


def stream_with_sdk() -> None:
    client = OpenAI(base_url="https://openrouter.ai/api/v1", api_key=API_KEY)
    stream = client.chat.completions.create(model=MODEL, messages=MESSAGES, max_tokens=120, stream=True)
    for chunk in stream:                      # the library does the SSE parsing for you
        delta = chunk.choices[0].delta.content if chunk.choices else None
        if delta:
            print(delta, end="", flush=True)
    print()


if __name__ == "__main__":
    stream_with_sdk() if "--sdk" in sys.argv else stream_by_hand()

Because the "200 OK" is committed as soon as the provider returns headers, a provider failure after that point shows up as a chunk with an error field, possibly as the very first chunk — so the script checks every chunk. Failures before that point (no provider available, rate limit, out of credits, bad key) still come back as a normal non-200 response with a JSON error body, so also check the status code before reading data: lines. Structured output: JSON in a shape you define

Free text is fine for humans; code needs fields. If brief is going to save a briefing with a title, a summary, a list of facts and a list of sources, it needs those as separate values it can rely on — not a paragraph it has to guess its way through. The switch for that is response_format with a JSON Schema: you describe the shape, and providers with a native strict mode constrain the model to produce exactly that shape (others treat the schema as a strong hint — one more reason to validate in code). Then json.loads() in Python turns it into a normal dictionary.

Two supporting settings: provider: {"require_parameters": true} tells the router to use only providers that actually honor response_format (support is per endpoint — the model must support it and so must the specific provider serving it — and unsupported parameters are otherwise silently ignored); and the response-healing plugin repairs slightly broken JSON — a missing bracket, a trailing comma — on non-streaming requests.

Usage:
    uv run brief/briefing.py "Why is the sky blue?"
"""

import json
import os
import re
import sys
from datetime import date
from pathlib import Path

import requests
from dotenv import load_dotenv

load_dotenv()
API_KEY = os.environ["OPENROUTER_API_KEY"]
URL = "https://openrouter.ai/api/v1/chat/completions"
MODEL = "mistralai/mistral-nemo"      # supports 'structured_outputs' (see brief/models.py)

# The shape we want back. JSON Schema is just a description of a JSON object:
# which fields exist, what type each is, and that nothing else is allowed.
BRIEFING_SCHEMA = {
    "type": "object",
    "properties": {
        "title": {"type": "string", "description": "Short headline, max 10 words"},
        "summary": {"type": "string", "description": "2-3 sentence plain-English summary"},
        "key_facts": {"type": "array", "items": {"type": "string"}, "description": "3-5 bullet facts"},
        "sources": {"type": "array", "items": {"type": "string"},
                    "description": "Only URLs starting with http that literally appear in the research text. Empty list if none."},
    },
    "required": ["title", "summary", "key_facts", "sources"],
    "additionalProperties": False,
}


def structure(question: str, research_text: str) -> tuple[dict, dict]:
    """Ask the model to reshape free text into our schema. Returns (briefing, usage)."""
    body = {
        "model": MODEL,
        "messages": [
            {"role": "system", "content": "You turn research notes into a briefing. Use only the facts in the notes. Never invent sources."},
            {"role": "user", "content": f"Question: {question}\n\nResearch notes:\n{research_text}"},
        ],
        "response_format": {                                   # <- the structured-output switch
            "type": "json_schema",
            "json_schema": {"name": "briefing", "strict": True, "schema": BRIEFING_SCHEMA},
        },
        "provider": {"require_parameters": True},              # only route to providers that honor response_format
        "plugins": [{"id": "response-healing"}],               # repair slightly-broken JSON (non-streaming only)
        "max_tokens": 400,
    }
    data = requests.post(URL, headers={"Authorization": f"Bearer {API_KEY}"}, json=body, timeout=90).json()
    if "error" in data:
        raise SystemExit(f"OpenRouter error: {data['error']}")
    briefing = json.loads(data["choices"][0]["message"]["content"])   # safe: the shape was enforced
    # The schema guarantees the SHAPE, not the TRUTH. Small models still invent "sources",
    # so we keep only real links. Never trust; always validate in code.
    briefing["sources"] = [s for s in briefing["sources"] if s.startswith("http")]
    return briefing, data["usage"] | {"model": data["model"]}


def save_markdown(question: str, briefing: dict) -> Path:
    slug = re.sub(r"[^a-z0-9]+", "-", question.lower()).strip("-")[:40]
    path = Path("briefings") / f"{date.today()}-{slug}.md"
    facts = "\n".join(f"- {f}" for f in briefing["key_facts"])
    sources = "\n".join(f"- {s}" for s in briefing["sources"]) or "- (none in the notes)"
    path.write_text(f"# {briefing['title']}\n\n_Question: {question}_\n\n{briefing['summary']}\n\n"
                    f"## Key facts\n{facts}\n\n## Sources\n{sources}\n")
    return path

CONCEPT 5
Tools: letting the model ask for things

A model cannot run code, read your files or search the web. What it can do is say, in a machine-readable way, "please run this function with these arguments". Your code runs it, sends the result back as a new message, and the model continues. That round trip is a tool call, and the loop around it is what people mean by an "agent".

The loop, written by hand

Two local tools let the model look at the briefings you have saved. Notice the four rules in the comments: describe each tool with a JSON Schema for its arguments; send the tools list on every turn; append the model's own message (the one containing tool_calls) before appending the tool result; cap the loop.

from dotenv import load_dotenv

load_dotenv()

# --- 1. The tools themselves: ordinary Python functions. ---
def list_saved_briefings() -> list[str]:
    return sorted(p.name for p in Path("briefings").glob("*.md"))


def read_briefing(filename: str) -> str:
    return (Path("briefings") / filename).read_text()[:2000]


TOOL_FUNCTIONS = {"list_saved_briefings": list_saved_briefings, "read_briefing": read_briefing}

# --- 2. How we describe them to the model (JSON Schema for the arguments). ---
TOOLS = [
    {"type": "function", "function": {
        "name": "list_saved_briefings",
        "description": "List the filenames of briefings saved on disk.",
        "parameters": {"type": "object", "properties": {}, "required": []},
    }},
    {"type": "function", "function": {
        "name": "read_briefing",
        "description": "Read one saved briefing by filename.",
        "parameters": {"type": "object", "properties": {"filename": {"type": "string"}}, "required": ["filename"]},
    }},
]


def run(question: str) -> None:
    messages = [{"role": "user", "content": question}]
    total_cost = 0.0

    for step in range(1, 6):                                            # 3. the loop, capped at 5 turns
        data = requests.post(URL, headers={"Authorization": f"Bearer {API_KEY}"}, json={
            "model": MODEL, "messages": messages, "tools": TOOLS, "max_tokens": 300,  # tools sent EVERY turn
        }, timeout=60).json()
        if "error" in data:
            raise SystemExit(f"OpenRouter error: {data['error']}")
        total_cost += data["usage"]["cost"]
        message = data["choices"][0]["message"]
        messages.append(message)                                         # keep the assistant turn (easy to forget!)

        if not message.get("tool_calls"):                                # plain text answer -> done
            print(f"\n[step {step}] final answer:\n{message['content'].strip()}")
            break

        for call in message["tool_calls"]:                               # 4. run what it asked for
            name = call["function"]["name"]
            args = json.loads(call["function"]["arguments"])             # arguments arrive as a JSON *string*
            result = TOOL_FUNCTIONS[name](**args)
            print(f"[step {step}] model asked for {name}({args}) -> {str(result)[:80]!r}")
            messages.append({"role": "tool", "tool_call_id": call["id"], "content": json.dumps(result)})

    print(f"\ntotal cost across {step} round-trips: ${total_cost:.6f}")


if __name__ == "__main__":

CONCEPT 6
Cost: measure, then pull the levers

This is the chapter the whole course builds toward. The arithmetic is simple: cost = input tokens × input price + output tokens × output price, plus any tool fees (a web search is about $0.007). OpenRouter does the sum for you and puts it in usage.cost on every response, so you never have to estimate. What you do have to decide is which model each step of your program deserves — and the only honest way to decide is to measure.

Measure: the same five questions on three tiers

Five questions with checkable answers, three models, and a strong fourth model scoring each answer 1–5. Answers are cached on disk so re-scoring costs nothing extra.

Lever 1 · Routing: where the request goes

The same model is often served by several providers at different prices and speeds. By default OpenRouter load-balances toward cheap, healthy ones. You can override it: provider.sort: "price" or "throughput" (strict order, no more balancing), the :floor suffix (cheapest, and it also admits discounted "flex" capacity), and provider.max_price — a hard ceiling that makes the request fail rather than pay more.

Lever 2 · Prompt caching: stop paying for the same prefix

If every request starts with the same long instructions, the provider can remember the processed prefix and charge you a fraction for it next time. OpenAI does this automatically once the prefix exceeds ~1,024 tokens; Anthropic needs a cache_control field (a single top-level one that OpenRouter places for you, or explicit markers on individual content blocks) and a minimum of 1,024–4,096 tokens depending on the model (cache writes cost 1.25×, reads 0.1×); Gemini and DeepSeek have their own rules. You see it working in usage.prompt_tokens_details.cached_tokens.

Lever 3 · Response caching: the same request, answered for free

Different layer, simpler idea: send the header X-OpenRouter-Cache: true and if the exact same request arrives again within the TTL (5 minutes by default, configurable), OpenRouter returns the stored answer at zero cost and no provider is called. Near-exact: whitespace is ignored, but a different key order in the JSON, temperature written out versus omitted, streaming versus not, or a different API key is a miss.

"""brief - research any question from the command line.

    uv run -m brief "What changed in the EU AI Act in 2026?"

Step 1: a mid-tier model searches the web (OpenRouter server tool) and streams an answer.
Step 2: a cheap model reshapes that answer into a fixed-schema briefing (title / summary / facts / sources).
Step 3: save it as markdown and print exactly what it cost.
"""

import json
import os
import re
import sys

import requests
from dotenv import load_dotenv

from brief.briefing import save_markdown, structure

load_dotenv()
API_KEY = os.environ["OPENROUTER_API_KEY"]
URL = "https://openrouter.ai/api/v1/chat/completions"
RESEARCH_MODEL = "anthropic/claude-haiku-4.5"


def research_streaming(question: str) -> tuple[str, list[str], dict]:
    """Web-search-backed answer, streamed to the terminal as it is written."""
    body = {
        "model": RESEARCH_MODEL,
        "messages": [
            {"role": "system", "content": "You are a research assistant. Search the web when the question needs "
                                          "current facts. Be concise. End with the URLs you used, one per line."},
            {"role": "user", "content": question},
        ],
        "tools": [{"type": "openrouter:web_search",
                   "parameters": {"max_uses": 2, "max_results": 3, "search_context_size": "low"}}],
        "max_tool_calls": 4,
        "max_tokens": 600,
        "stream": True,
    }
    text, urls, usage, served_by = [], [], {}, RESEARCH_MODEL
    with requests.post(URL, headers={"Authorization": f"Bearer {API_KEY}"}, json=body, stream=True, timeout=180) as r:
        for line in r.iter_lines(decode_unicode=True):
            if not line or line.startswith(":") or not line.startswith("data: "):
                continue
            payload = line[6:]
            if payload == "[DONE]":
                break
            chunk = json.loads(payload)
            if "error" in chunk:
                raise SystemExit(f"OpenRouter error: {chunk['error']}")
            served_by = chunk.get("model", served_by)
            if chunk.get("usage"):
                usage = chunk["usage"]
            for choice in chunk.get("choices", []):
                delta = choice.get("delta", {})
                if delta.get("content"):
                    text.append(delta["content"])
                    print(delta["content"], end="", flush=True)
                for a in delta.get("annotations") or []:
                    if a.get("type") == "url_citation":
                        urls.append(a["url_citation"]["url"])
    print()
    answer = "".join(text)
    urls = list(dict.fromkeys(urls or re.findall(r"https?://\S+", answer)))   # de-duplicate, keep order
    return answer, urls, usage | {"served_by": served_by}


def main() -> None:
    if len(sys.argv) < 2:
        raise SystemExit(&#x27;usage: uv run -m brief "your question"')
    question = " ".join(sys.argv[1:])

    print(f"▸ researching with {RESEARCH_MODEL} (web search on)…\n")
    answer, urls, research_usage = research_streaming(question)

    print("\n▸ structuring the briefing…")
    notes = answer + "\n\nSources:\n" + "\n".join(urls)
    briefing, structure_usage = structure(question, notes)
    path = save_markdown(question, briefing)
    print(f"▸ saved {path}")

    searches = (research_usage.get("server_tool_use_details") or {}).get("web_search_requests", 0)
    total = research_usage.get("cost", 0) + structure_usage["cost"]
    print(f"▸ cost: ${total:.4f} · {research_usage.get('prompt_tokens', 0):,} in / "
          f"{research_usage.get('completion_tokens', 0):,} out · {searches} web search(es) · "
          f"answered by {research_usage['served_by']}, structured by {structure_usage.get('model', 'cheap model')}")


if __name__ == "__main__":
    main()

## What is OpenRouter?

**OpenRouter** is a unified API platform that provides access to multiple large language models (LLMs) from different providers through a single interface. Key features include:

- **Multi-model access**: Access to 500+ models from 80+ providers
- **Unified billing**: Aggregate all your LLM usage in one place with consolidated analytics
- **Pass-through pricing**: You pay the same rates as you would directly from providers, with no markup on inference pricing
- **Improved uptime**: Pools uptime across providers with fallback capabilities
- **No subscriptions**: Pay-as-you-go model

## Cost Structure

OpenRouter offers several pricing tiers:

1. **Free Plan**
   - 25+ free models with 50 requests/day limit
   - 4 free providers
   - Limited workspace (5)
   - No platform fees, but limited to free models

2. **Pay-as-You-Go**
   - 5.5% platform fee on credit purchases ($0.80 minimum)
   - Access to 500+ models and 80+ providers
   - Credit-based system (no subscriptions)
   - Pass-through pricing from providers
   - $25,000/month free allowance for Bring Your Own Keys (BYOK)

3. **Business Plan**
   - 8% platform fee
   - 500+ models and 80+ providers
   - Enhanced features (auto-routing, budgets, caching, admin controls)
   - $25,000/month free BYOK allowance

4. **Enterprise Plan**
   - Custom fee discounts
   - 500+ models and 80+ providers
   - Full feature set including SSO/SAML
   - $200,000/month free BYOK allowance

**Payment**: Users add credits to their account and pay per token used. New users receive a small free allowance to get started.

GLOSSARY
Every term used above, one line each

API
A web address that accepts requests in an agreed format and returns responses in an agreed format. Programs talk to services through APIs.
API key
A long secret string that identifies (and bills) your account. Lives in .env, never in code or chat.
Model
One specific AI, e.g. anthropic/claude-haiku-4.5. The part before the slash is who made it.
Provider
The company hosting a model for you — often several per model, at different prices.
Endpoint
One model at one provider (OpenRouter's term). Also used loosely for the API address itself.
Token
The unit models read and write in; roughly ¾ of an English word. Prices are per token; humans quote per million.
Prompt / completion
What you send in / what comes back. Also "input / output". Output is usually 2–5× more expensive.
Context length
The maximum total size of one conversation (input and output together), in tokens.
Messages, roles
The conversation as a list. system = standing instructions, user = you, assistant = the model, tool = a tool's result.
Temperature
Randomness dial, 0–2. 0 repeats itself; 1 is normal; 1.5+ produces word salad.
max_tokens
Cap on answer length — and therefore on spend. Hidden reasoning tokens count against it.
finish_reason
Why the model stopped: stop (done), length (hit the cap), tool_calls (wants a tool), error.
JSON
The text format requests and responses are written in: {"key": "value"}. Python's dict after json.loads.
JSON Schema
A description of an allowed JSON shape — which fields, which types, which are required. Used for structured output and tool arguments.
Structured output
Forcing the model to answer in a JSON shape you defined (response_format).
Streaming / SSE
Receiving the answer in small chunks as it is written, over a kept-open connection ("Server-Sent Events").
Tool / function calling
The model asks your code to run a named function with arguments; you return the result; it continues.
Server tool
A tool OpenRouter runs for you (web search, fetch, advisor…), declared with an openrouter: prefix.
Agent
A program that loops: ask the model → run the tools it asks for → repeat until it answers.
Fallback
A list of models or providers to try in order if the first fails.
Alias (~…-latest)
A name that always resolves to the newest model in a family.
Variant suffix
:free, :batch (separate catalog entries) and :nitro, :floor, :exacto (routing hints).
Prompt caching
The provider remembers a long identical prefix and charges a fraction for it next time.
Response caching
OpenRouter returns the stored answer to an identical request, free.
Reasoning tokens
Hidden "thinking" some models do before answering. Billed as output; counted against max_tokens.
SDK
A library that wraps an API in ordinary functions (openai, openrouter).
uv
The Python project tool used here; uv run file.py runs a script with its libraries ready.

Request template

# POST https://openrouter.ai/api/v1/chat/completions
# Header: Authorization: Bearer $OPENROUTER_API_KEY
{
  "model": "mistralai/mistral-nemo",           # or "models": [...] for fallbacks
  "messages": [
    {"role": "system", "content": "You are ..."},
    {"role": "user",   "content": "..."}
  ],
  "max_tokens": 300,                          # cap length = cap spend
  "temperature": 0.7,                         # 0 repeatable ... 1 normal
  "stream": false,                            # true = chunks as they are written
  "response_format": {"type": "json_schema", "json_schema": {"name": "x", "strict": true, "schema": {...}}},
  "tools": [{"type": "function", "function": {...}}, {"type": "openrouter:web_search"}],
  "provider": {"sort": "price", "require_parameters": true, "max_price": {"prompt": 1, "completion": 5}},
  "reasoning": {"effort": "none"}               # or "low"; "none" only where reasoning is optional
}

CHECK YOURSELF
If you can answer these, you have it

1. A response says "model": "mistralai/mistral-nemo" but you asked for ~openai/gpt-mini-latest with a fallback list. What happened, and what were you billed for?
The first choice failed (or the alias resolved elsewhere) and OpenRouter used the next model in your list. You are always billed for the model named in the response — that field is the source of truth.
2. The catalog says "completion": "0.00001". What does a 500-token answer cost?
$0.00001 is per token, so × 1,000,000 = $10 per million. 500 tokens × $0.00001 = $0.005, half a cent.
3. You get HTTP 200 but the answer is empty. Name two things to check.
The body may contain an error field (200 is sent before the provider finishes); and finish_reason may be length with reasoning_tokens having eaten max_tokens.
4. Why does brief filter sources to strings starting with http even though the schema already defines a sources list?
The schema guarantees the shape (a list of strings), not the truth. A small model filled it with invented titles. Only code can enforce "must be a real link".
5. In the hand-written tool loop, why is tools sent on every turn, and what must be appended before the tool result?
The router validates tools on each call, so they must be present every time. The assistant message containing tool_calls must be appended first, so the tool_call_id in your result has something to pair with.
6. A step in your pipeline reshapes text into JSON. Which tier, and why?
Cheap. Mechanical, well-specified tasks scored a perfect 5 on the cheap model for a thousandth of the price. Spend on judgement, not on reformatting.
7. What is the difference between prompt caching and response caching?
Prompt caching happens at the provider: an identical long prefix is remembered and charged at a fraction. Response caching happens at OpenRouter: an identical whole request gets the stored answer back, free. They stack.
8. When would you set provider.max_price, and what is the risk?
To guarantee you never pay above a ceiling per million tokens. The risk: it is a hard filter — if no provider is cheap enough the request fails (404 "No endpoints found…") rather than running.
