Key finding: **the `pptfiles/` (python-pptx) versions of the packets are strictly richer than the `pdfiles/` (pymupdf4llm) versions of the same packets** — 265 KB vs 154 KB for cfpacket2spr25, 146 KB vs 91 KB for valpacket2spr25 — because the pptx path captures Damodaran's speaker notes, which are first-person teaching prose ("It always helps to lay a philosophical foundation…"). `grep -c '^### Notes:'` on the pdfiles versions = 0. **Prefer pptfiles, drop the pdfiles twins.**

`podcasts/*/sessionNslides.md` are page-range slices of the Spring-2024 packet PDF (each file's `# valpacket1spr24` title gives it away). Content ≈ 90% redundant with the spr25/spr26 packets, but they carry the only explicit **session-number → content mapping** in the corpus. Use them to build a session index, not as primary retrieval text.

## 6. Suggested chunking + metadata

Chunking by source type (target 800–1,200 tokens, 15% overlap, `text-embedding-3-large` or voyage-3):
| source_type | Split on | Target |
|---|---|---|
| `blog` | `##`/`**bold**` sub-heads, never across posts | 900 tok, prepend `title` + `date` to every chunk |
| `slide_deck` | `<!-- Slide number: N -->` boundary; **keep slide body + its `### Notes:` in one chunk** | 1 slide = 1 chunk, merge runs of tiny slides up to 600 tok |
| `packet` | slide/page marker from the `<!-- source: ... N pages -->` header | 1,000 tok |
| `book` | `# **CHAPTER n**` → `## SECTION` → `### sub`; keep `ILLUSTRATION n.n` intact | 1,200 tok |
| `transcript` | header line, then ~60–90 s of speech (≈700 tok) after punctuation restore | 800 tok, 20% overlap |
| `dataset` | keep the whole "Explanation & FAQs" block as one chunk; table rows chunked by 40 rows with the header repeated | varies |
| `site_page` | `#`/`##` headings; drop chunks that are >50% links | 900 tok |
| `exam` | one question + its solution = one chunk (join `X.md` with `Xsoln.md`) | whole Q&A |
| `filing` | Item boundaries (Item 1A, Item 7, Item 8) | 1,200 tok |

Metadata schema (every chunk):
```
id                 sha1(path + chunk_index)
source_type        blog | slide_deck | packet | book | transcript | dataset
                   | site_page | exam | filing | email | paper | article
title              from front matter / H1 / transcript header
author             "Aswath Damodaran" | third_party   <-- set false for New_Home_Page/articles, LB2, filings
date               ISO; blog front matter, packet term, transcript upload, filing period
year               int (for recency-preferring rerank: spr26 > spr25 > spr24)
course             valuation | corp_finance | inv_philosophy | clc | seminar | none
course_level       mba | ug | exec | online | none
term               spr25 | spr26 | spr24 | fall16 | ...
session            int (from sessionN.md, sessionNslides.md, transcript title "Session N: ...")
topic              erp | beta | cost_of_capital | terminal_value | multiples | dividends
                   | capital_structure | real_options | distress | narrative | lifecycle | ...
region             us | india | europe | japan | china | emerging | global   <-- enables India filtering
company            AAPL | ZOMATO | TSLA | ... (from pc/blog, LB2, filings)
url                canonical NYU/blogspot/YouTube URL (blog front matter has it; transcripts have it in the header line)
path               absolute source path in financeMD / tar member path
page               PDF page or slide number when known
video_id           YouTube id
playlist_ids       [] (multi-valued after dedup)
converter          pymupdf4llm | python-pptx | pandoc | blogger-structured | pandas-pipe-tables
has_speaker_notes  bool (pptx-derived)
quality            clean | needs_punctuation | ocr_ligature_damaged | table_only
token_count        int
```
Retrieval notes: (1) filter `author == "Aswath Damodaran"` by default so press clippings and filings can't be quoted as his view; (2) boost by `year` so a "current ERP" question hits the 2026 data update, not the 2015 one; (3) `region == india` is a cheap high-precision filter given 24 India datasets + 8 India blog posts + val2dayIndia2025; (4) route "what is the number today" questions to the spreadsheet tool, not the vector index.

OPEN QUESTIONS:
 - Should the 2012 and 2025 blog years be refetched from aswathdamodaran.blogspot.com before ingest, or is shipping with that gap acceptable for v1? 2025 contains a full data-update series that users will ask about.
 - Is the assistant meant to speak only as Damodaran? That decides whether New_Home_Page/articles/ (127 third-party Forbes/WSJ/NYT clippings), the LB2 filings, and the AFML / Deep-Learning-for-Finance books go into the same index, a separate index, or are excluded.
 - Should class transcripts (~62 MB deduped) go through a punctuation-restoration / admin-chatter-stripping LLM pass before embedding? That is a real cost (~16M tokens through a cheap model) but raw auto-captions retrieve poorly. Alternative: ship Tier 1+2 without them and add later.
 - Do you want the 2026 numeric datasets (ERP, country risk premium, industry betas/WACC) exposed as a live lookup tool rather than embedded text? Embedding pc/archives/ costs 6.5M tokens and still answers numeric questions badly.
 - For spr25 vs spr26 packets: keep both with a year field so 'what changed this year' questions work, or replace spr25 entirely with spr26?
 - Which vector store and embedding model? The transcripts meta pack shows a prior Pinecone attempt — reuse Pinecone, or switch (pgvector / Chroma / Turbopuffer)?
 - Is India-specific coverage a first-class product requirement (region filter, India defaults for risk-free rate and ERP), or just one topic among many?
 - Should chunk text be stored verbatim or lightly cleaned (Blogger div wrappers, googleusercontent image URLs, nav headers, [Music] markers stripped)? Cleaning helps retrieval but breaks exact-quote citation back to the source file.
