## 1) pi.dev — the "pi" coding agent / harness (Mario Zechner, `badlogic/pi-mono`)

**What it is.** A terminal-first, open-source AI coding agent + agent *harness* by Mario Zechner (`badlogic`, creator of libgdx). Tagline on the site: "a minimal agent harness. Adapt Pi to your workflows, not the other way around." Monorepo `github.com/badlogic/pi-mono` started Aug 2025; npm packages are published under the Earendil Inc. scope (`@earendil-works/pi-coding-agent`, `pi-agent-core`, `pi-ai`). (https://pi.dev/, https://github.com/badlogic/pi-mono)

**What "harness" means here.** The harness is the scaffolding *around* the model: task intake, context assembly (what actually goes into the prompt), the tool set, the agent loop (call model → run tool → feed result back), permission/sandboxing, failure handling, and the terminal UI. The model is the engine; the harness is the car. Claude Code, OpenCode, Cursor and pi are all harnesses over the same underlying LLM APIs. pi's differentiator is deliberately *small*: ~4 core tools and a system prompt reportedly under ~1,000 tokens, on the philosophy that what you leave out matters more than what you put in. A Databricks benchmark (Aug 2026, as reported) found pi sent roughly 3x less context per turn than competing harnesses, which directly cuts token cost. (https://explainx.ai/blog/pi-minimal-agent-harness-mario-zechner-guide-2026, https://dev.to/wonderlab/one-open-source-project-a-day-no-53-pi-mono-minimalist-high-performance-ai-coding-agent-4d73)

**Extension / skills model** (four layers, all yours to write):
| Layer | What it is |
|---|---|
| Extensions | TypeScript modules with access to tools, slash commands, keyboard shortcuts, events, and the TUI |
| Skills | On-demand capability packages = instructions + tools (loaded only when relevant, to save context) |
| Prompt templates | Reusable Markdown prompts invoked as slash commands |
| Themes | Visual styling |

Install community packages with `pi install npm:@foo/pi-tools` or `pi install git:github.com/user/repo`. Ships 50+ example extensions (sub-agents, plan mode, permission gates, sandboxing). Notable: **pi has no built-in permission system** — the README says it "does not include a built-in permission system for restricting filesystem, process, network, or credential access"; you are expected to containerize/sandbox it yourself. That is a real beginner footgun versus Claude Code's default permission prompts.

**Providers (15+).** Anthropic, OpenAI, Google, Azure, Bedrock, Mistral, Groq, Cerebras, xAI, Hugging Face, Kimi For Coding, MiniMax, NVIDIA, OpenRouter, Ollama; custom providers via config or extension. Switch mid-session with `/model` or Ctrl+L.

**Open source / pricing.** MIT licensed. The software is free. There is no subscription — you pay whatever your chosen model provider charges (BYO API key, or route through OpenRouter).

## 2) OpenCode (opencode.ai, SST → Anomaly) + three-way comparison

**What it is.** MIT-licensed open-source coding agent from the SST team (now under the Anomaly org). Terminal TUI, plus a desktop app and IDE extensions. Plan-then-Build split so you review proposed edits before they land; LSP diagnostics; undo/redo; shareable session links. Rewritten in TypeScript/Bun (the archived Go repo `opencode-ai/opencode` is dead — stopped Sept 2025; the live one is the SST/Anomaly one). ~160k–190k GitHub stars in 2026. (https://opencode.ai/docs/, https://www.datacamp.com/blog/what-is-opencode)

**Providers.** Via the Models.dev registry: **75+ providers** including Anthropic, OpenAI, Google, DeepSeek, Groq, and local models via Ollama. Also **OpenCode Zen**, an optional first-party gateway: 50+ curated/benchmarked coding models, pay-as-you-go with *no markup*, ~6 free models at any time, plus a **Zen Go** flat plan at **$10/mo** with caps ($12/5h, $30/wk, $60/mo) over 24 open-weight coding models. Zen is explicitly optional. (https://opencode.ai/docs/zen/, https://opencode.ai/zen)

**CRITICAL for this user — the Anthropic OAuth story.** Timeline:
- **2026-01-09**: Anthropic began server-side rejection of Claude Pro/Max OAuth tokens used by third-party tools ("This credential is only authorized for use with Claude Code").
- **2026-02-19**: Anthropic's legal/compliance docs added an authentication-and-credential-use position: subscription OAuth tokens are for Claude Code / Claude.ai only; the Agent SDK requires API-key auth.
- **2026-03-19**: OpenCode merged a PR ("anthropic legal requests") removing the Anthropic OAuth plugin and all Claude Pro/Max auth.
- **2026-04-04**: third-party tools formally blocked from Claude Pro/Max quota.
- **2026-05-13**: Anthropic **reinstated** third-party agent use on subscriptions, but via a separate, **non-rollover monthly "Agent SDK credit" pool** billed at API list rates: **Pro $20/mo, Max 5x $100/mo, Max 20x $200/mo, Team/Enterprise $100–$200/seat**. Interactive Claude Code usage is unaffected; programmatic/third-party usage draws only from that pool. (https://venturebeat.com/technology/anthropic-reinstates-openclaw-and-third-party-agent-usage-on-claude-subscriptions-with-a-catch, 2026-05-13; corroborated by https://www.zbuild.io/resources/news/opencode-blocked-anthropic-2026 and https://tech-insider.org/ie/claude-code-agent-pricing-split-2026/)

Caveat: I could not find the exact "Authentication and credential use" wording in Anthropic's public consumer-terms or commercial-terms pages I fetched; the clause is reported by multiple secondary sources and by the enforcement error strings. **Verify on Anthropic's own legal/usage page before relying on it.**

**Three-way comparison**

| | **Claude Code** | **OpenCode** | **pi** |
|---|---|---|---|
| License | Closed-source product | MIT | MIT |
| Model lock-in | Anthropic only | 75+ providers via Models.dev, or Zen gateway | 15+ providers, incl. OpenRouter & Ollama |
| Auth to Claude | Native — Pro/Max subscription covers interactive use | API key, or subscription only via the capped Agent-SDK credit pool | same constraint as OpenCode |
| Extensibility | Skills, subagents, hooks, MCP, plugins — curated | Custom commands, themes, formatters, MCP, agents | Extensions/Skills/templates in TypeScript; you build the harness |
| UI | TUI + desktop + IDE | TUI + desktop app + IDE extensions | TUI |
| Permissions/sandbox | Built-in permission prompts by default | Plan-then-Build review gate | **None built in** — you sandbox it |
| Cost | $20 Pro / $100 Max5x / $200 Max20x, or API | Free software; BYOK, or Zen PAYG, or Zen Go $10/mo | Free software; BYOK / OpenRouter |
| Setup effort for a beginner | Minutes | ~30 min (keys + config) | Highest — "harness engineering required" |
| Benchmarks | Fastest/most instruction-following in head-to-heads | Builder.io early-2026 test: OpenCode 78% slower on identical tasks with Sonnet 4.5 | ~3x less context/turn (Databricks, Aug 2026) → cheaper |

**Verdict for this user:** stay on **Claude Code**. He already pays for it, it is the lowest-friction path, it has the permission system a beginner needs, and MCP + Skills already cover the extensibility he'll want for a valuation app. OpenCode is the right *second* tool — install it free, keep it configured with a cheap model (Zen free tier or an OpenRouter key) for high-volume grunt work (bulk file conversion, scraping loops, repetitive refactors) so those tokens don't eat the Claude quota. **pi is not recommended yet**: no built-in permission system, and it expects you to write your own harness in TypeScript — that is a project, not a tool, and it competes for the time he should spend on valuation logic.

## 3) OpenRouter

**What it is.** One OpenAI-compatible API gateway, one API key, one credit balance, one base URL, in front of hundreds of models from dozens of providers. Swap models by changing a string. Adds automatic fallback/routing across providers of the same model.

**Billing (2026).**
- **Credits model**: buy credits, spend per token. **5.5% fee on credit purchases, with an ~$0.80 minimum per purchase** → effective 8–16% on purchases under $20. Buy in larger chunks to amortize.
- **Per-token rates** are pass-through: at or very close to direct provider list price for most popular models.
- **BYOK** (bring your own provider key): **$0 fee up to $25,000/month of list-price inference** on Pay-as-you-go ($200,000/mo Enterprise), then 5% on the excess. Some sources describe it as 1M free BYOK requests/month then 5%; treat the exact BYOK terms as needing verification on openrouter.ai/docs.
- **Sept 2026**: new self-serve **Business tier at 8%** platform fee, which pins inference to EU-only or US-only providers with no cross-region fallback (data-residency play).
(https://ofox.ai/blog/openrouter-pricing-hidden-markup-breakdown-2026/, https://www.truefoundry.com/blog/openrouter-pricing, https://apimart.ai/blog/openrouter-pricing-explained-model-costs-credits-provider-routing)

**When a solo dev needs it vs calling Anthropic/OpenAI directly:**
- **Use OpenRouter when**: you want to A/B many models cheaply; you want one billing relationship instead of 5 signups; you want automatic failover; you want access to open-weight models (Qwen, DeepSeek, Kimi, Llama) without standing up inference yourself; you're prototyping and don't know which model wins.
- **Go direct when**: you've settled on one or two models and are running real volume — you then save the 5.5% and get first-class features (Anthropic prompt caching, batch API 50% discount, extended thinking controls) that gateways sometimes lag on.
- **For this project**: direct Anthropic for the main valuation reasoning; an OpenRouter key as the cheap side-channel for bulk/embarrassingly-parallel jobs (summarizing 54 transcripts, tagging 100+ datasets) and for benchmarking a cheap open-weight model against the expensive one.

## 4) "Fine-tuned harness" vs "fine-tuned open-weight model"

**Fine-tuned harness (the cheap, right thing).** You do not touch the model's weights. You shape the *scaffolding*: system prompt, the tool set, which files/skills get loaded when, retrieval, output schemas, evals. In Claude Code terms: CLAUDE.md + Skills + MCP servers + subagents + slash commands. Cost: your time. Reversible in seconds. This is what "adapt the harness to your workflow" means and it is 90% of the value for a domain app.

**Fine-tuned open-weight model.** You take a model whose weights are downloadable (Llama, Qwen, Mistral, Gemma, DeepSeek) and run additional training on your own examples so its *behavior* changes — output format, tone, refusal patterns, a consistent reasoning style. Usually done with **LoRA/QLoRA**: you train a small adapter (a few million params) instead of all weights, which is why it's affordable.

**Is it realistic for a solo beginner in 2026 for financial valuation? — Almost certainly not, and not yet.** Evidence both ways:
- **Cost is genuinely low.** FinLoRA (arXiv 2505.19819, 2025-05-26; Open-Finance-Lab) fine-tuned Llama-3.1-8B on 19 financial datasets incl. 4 novel XBRL-analysis sets over 150 SEC filings: 14.1–15.9 wall-clock hours on 4× A5000 = ~56–64 GPU-hours ≈ **$14.66–$16.54** at $0.26/GPU-hr. Result: vanilla LoRA (8-bit, rank 8) scored 74.74 avg vs 37.05 base — a **+37.69 point / ~36% average lift**. So the compute is trivially affordable. (https://arxiv.org/abs/2505.19819, https://finlora-docs.readthedocs.io/en/latest/benchmark_results/overview.html)
- **The data and the lifecycle are where it dies.** The accepted 2026 sequencing is **Prompt → RAG → Fine-tune → Distill**, and the standing advice is "fine-tuning is for *form*, not *facts* — style, structured output, refusal patterns — not for knowledge that changes weekly." You need ~500–1,000 hand-curated high-quality input/output pairs, and budget 3–5x the training cost for 12 months of retraining/eval ownership. (https://bigdataboutique.com/blog/fine-tuning-llms-when-rag-isnt-enough, https://www.layer3labs.io/open-weights/fine-tuning-open-weights-models)
- **Applied to this project**: Damodaran's method is *facts + arithmetic + a book of rules*. Cost of capital tables, ERPs, industry betas, lease-capitalization rules, R&D capitalization rules — these change annually and live in the corpus he already has on disk. That is a textbook RAG + deterministic-code problem, not a weights problem. A fine-tune would be justified only later, and only for **form**: e.g. forcing a model to always emit a valid DCF-assumption JSON block, or to always flag when a growth assumption violates the reinvestment-rate identity. Even then, prompt + JSON schema + a validator function gets you most of the way for $0.

**Bottom line:** RAG over the Damodaran corpus + prompting + deterministic Python for the actual math. Revisit fine-tuning only if, after 6+ months, you have logged 1,000+ real (input, corrected-output) pairs from your own app and a specific formatting/behavior failure that prompting cannot fix.

## 5) Artificial Analysis (artificialanalysis.ai)

**What the site measures.** Independent third-party benchmarking of AI models *and* the providers/endpoints serving them, on three axes: **intelligence, speed, price**. Current headline: **Artificial Analysis Intelligence Index v4.3**, an aggregate of 10 evals (AA-Briefcase, GDPval-AA v2, AutomationBench-AA, Terminal-Bench v4.0, SciCode, and others). Sub-indices include a **Coding Agent Index (v1.5)**, a **Finance & Accounting Index**, an **Openness Index**, Elo arenas for image/video/speech, plus per-provider endpoint output speed, latency, accuracy and cost-per-task.

**The Search Index** (launched **2026-08-18**): benchmarks **search API providers** — not models — on quality, cost and speed *as used by an agent*. Method: same model (GPT-5.6 Luna), same agent scaffold (Stirrup, AA's open-source framework), 25 runs per task; the only variable swapped is the search provider. Score = equal-weighted mean of three benchmarks:
| Benchmark | What it tests | Size |
|---|---|---|
| DeepSearchQA | broad research questions needing multiple queries; F1-scored | 900 tasks |
| BrowseComp | hard-to-find facts requiring multi-hop browsing; exact match | 200-task subset |
| AA-Omniscience | factual recall across 6 knowledge domains; accuracy | 600 tasks |

Launch coverage: 11 results across 7 providers — **Parallel, Exa, Firecrawl, You.com, Keenable, Tavily, Brave** (Perplexity and TinyFish also appear). Top scores: **Parallel Search (advanced) 75, Exa (auto) 74, Firecrawl 73**; no-search baseline = **33**. Cost for search alone ranges **$13.64 per 1,000 tasks (Parallel turbo) to $126 (Tavily basic)**; all-in with model tokens **$44.94–$80.53 / 1,000 tasks**. (https://artificialanalysis.ai/articles/search-api, 2026-08-18; https://artificialanalysis.ai/agents/search-api; https://artificialanalysis.ai/methodology/search-api)

**Relevance to a valuation app: mostly indirect, one direct use.**
- **Not relevant** for the core product. A long-horizon fundamentals platform should read *structured* data from SEC EDGAR / NSE filings / a fundamentals API, not web search. Search quality doesn't fix a wrong cash-flow number.
- **Relevant** for (a) the qualitative layer — news, management commentary, competitive context, "what changed this quarter" — where you'd pick a search API and the Index tells you Exa/Parallel/Firecrawl lead and roughly what per-query cost to expect; and (b) it's the one place with an apples-to-apples *cost* table, so it's a good budgeting reference if you add a news/research feature.
- The main index (Intelligence + price/speed) **is** directly useful: use it to pick the cheapest model that clears your quality bar for the bulk summarization work.

**Postgres + pgvector managed**
| | Supabase | Neon |
|---|---|---|
| Free | 500 MB DB, 1 GB file storage, 5 GB egress + 5 GB cached, 50k MAU, **2 active projects**, **pauses after 1 week idle** | 0.5 GB storage/project, 100 CU-hours/project, 10 branches, 100 projects, autoscale to 2 CU (8 GB RAM), 5 GB egress |
| Paid entry | **Pro $25/mo**: 8 GB disk included then $0.125/GB, 250 GB egress, 100 GB file storage, 100k MAU, includes $10 compute credit (covers one Micro instance) | **Launch**: compute $0.106/CU-hr, storage $0.35/GB-mo, autoscale to 16 CU, 500 GB egress/project |
| Compute add-ons | Micro $10, Small $15, Medium $60 /mo | Scale: $0.222/CU-hr |
| pgvector | yes | yes, all plans |
(https://supabase.com/pricing, https://neon.com/pricing)

**Standard advice for ~50–100 MB of text.** Do the arithmetic: 100 MB of text ≈ 25M tokens ≈ **~50,000–70,000 chunks** at 400–500 tokens/chunk. At 1536-dim float32 that's ~6 KB/vector = **~300–420 MB of vectors**, or ~half that at 768-dim, or ~4x less with halfvec/int8 quantization. That is **tiny**.

The consensus is unambiguous: **use Postgres + pgvector.** Below 10M vectors (you're at ~0.05–0.07M, i.e. 100–200x under) pgvector with an HNSW index returns in <50 ms and you get SQL JOIN/GROUP BY/window functions against your *fundamentals tables in the same database* — which matters enormously here, because you will constantly want "semantic match on Damodaran's text AND ticker = X AND fiscal_year >= 2023". Pinecone's metadata filtering can't express that. The crossover where Pinecone wins is somewhere around **50–100M vectors**, or when you refuse to spend any time tuning HNSW params. (https://encore.dev/articles/pgvector-vs-pinecone, https://selfhost.dev/blog/pgvector-vs-pinecone/, https://www.kunalganglani.com/blog/pgvector-vs-pinecone)

**Practical note on the free tiers**: Supabase Free's **500 MB DB** may be tight once vectors + fundamentals coexist, and the **1-week-idle auto-pause** is annoying for a hobby project you touch weekly. Neon Free gives 0.5 GB/project but across **100 projects** and scales-to-zero by design (no pause penalty). For $0, Neon is the better fit for this workload; for $25/mo, Supabase Pro (8 GB) removes all doubt and bundles auth/storage. Pinecone Starter's 2 GB would fit too, but you'd be splitting your data across two systems for no benefit.

### 8C. Recommended starting stack (solo builder, small budget)

4. **Damodaran's own datasets** (already on disk: `damodaran/pc/datasets/`, data-current 2026 zips) for ERPs, industry betas, cost of capital, multiples — these are the inputs his method actually needs and he publishes them annually for free.

**Phase 1 — first paid tier when free hits a wall (~$20–60/mo)**
5. **EODHD ALL-IN-ONE $99.99/mo** or **Fundamentals Feed $59.99/mo** if you need one vendor for India + global fundamentals with a clean license for personal use. Alternatively **indianapi.in** for India-only fundamentals at a lower price point (verify tier pricing).
6. **Kite Connect ₹500/mo** if and when you need accurate India price/corporate-action data you can trust (requires a Zerodha account, which he may already have).

**Phase 2 — only if you go commercial**
7. Replace yfinance and any scraped source entirely. Buy an FMP **Data Display and Licensing Agreement** or an EODHD commercial license. Move Vercel to Pro. Budget $150–400/mo.

### 8D. Licensing/redistribution rules to write down now
- **SEC EDGAR**: US-government work, public domain — free to display and redistribute. The only truly unencumbered source.
- **Damodaran's datasets**: published free on the NYU site for educational use. Attribute him; don't resell the raw tables.
- **Yahoo/yfinance**: ToS-prohibited for automated + commercial use. hiQ v. LinkedIn (2022) means scraping public data isn't a CFAA crime, but **it does not override contract/ToS**. Personal use only.
- **screener.in / Tickertape / Tijori**: consumer products, no redistribution rights, no public API. Manual validation only.
- **NSE/BSE**: free daily bhavcopy files are fine for your own app; **commercial redistribution and real-time feeds require a licensing deal with the exchange**.
- **Broker APIs (Kite/Upstox/Dhan/Breeze)**: data licensed for *your* use only — explicitly cannot be pushed to other platforms or other users.
- **FMP**: display/redistribute → separate Data Display and Licensing Agreement.
- **EODHD**: paid plans are personal-use; commercial needs enterprise pricing.
- **Design implication**: store a `source` and `license_class` column on every fact you ingest. Then "can I show this publicly?" becomes a query, not a panic.

## 9) MCP (Model Context Protocol) + existing financial MCP servers

**What it is.** An open standard, introduced by Anthropic in **Nov 2024**, that standardizes how LLM applications connect to external tools and data sources — "USB-C for AI tools." A *client* (Claude Code, Claude Desktop, Cursor, etc.) speaks MCP to any number of *servers*, each exposing tools, resources and prompts. Reference SDKs in TypeScript and Python.

**2026 status.** Adopted by OpenAI, Google, Microsoft, IBM, AWS. **Dec 2025: Anthropic donated MCP to the Agentic AI Foundation under the Linux Foundation** (launched 2025-12-09 with Anthropic, Block, OpenAI as co-founders; AWS, Google, Microsoft, Cloudflare, Bloomberg as platinum members). Spec versions: 2025-03-26, 2025-06-18, 2025-11-25, with a 2026-07-28 release candidate. ~97M monthly SDK downloads, 10,000+ active servers reported as of Dec 2025. (https://en.wikipedia.org/wiki/Model_Context_Protocol, https://www.anthropic.com/news/model-context-protocol)

**Financial MCP servers that exist today and plug into Claude Code:**
| Server | Covers | Notes |
|---|---|---|
| **EdgarTools MCP** (edgartools.io) | SEC EDGAR — 13 tools: financial statements, insider trading, company filings, live SEC data | Free, open source, **no API key required**. Strongest candidate for the US side |
| **SEC EDGAR MCP** (various, incl. an Apify-hosted one — marked DEPRECATED) | 13M+ filings | Prefer EdgarTools |
| **FinStack MCP** (`github.com/finstacklabs/finstack-mcp`) | **India-first**: live NSE/BSE quotes, Nifty 50, Sensex, Bank Nifty, fundamentals, analytics + SEC EDGAR + US quotes, crypto, forex | Open source. Best India-side starting point |
| **Kai Stock Market MCP** (`github.com/neerajadhav/kai-stock-market-mcp`) | Indian market data via **yfinance**, NSE-optimized, full global support | Open source; inherits yfinance's ToS caveats |
| **Yahoo Finance MCP** (`mcp-server-yfinance`) | Historical prices, dividends, splits, company info | Open source |
| **Financial Datasets MCP** (docs.financialdatasets.ai/mcp-server) | Income stmt, BS, CF, historical prices, market news | Official, runs locally, API key needed |
| **Polygon MCP** | Polygon.io official | Needs a Polygon key |

**How this user should use it.** MCP is the right extensibility surface for Claude Code here — no need for pi or OpenCode. Concretely: wire **EdgarTools MCP** (free, no key) + **FinStack MCP** (India) into Claude Code, and later write **your own MCP server** wrapping your Postgres fundamentals DB and your DCF engine. Then Claude Code can query your own valuation data directly rather than you pasting numbers. Writing an MCP server in Python is ~50 lines with FastMCP — this is the single highest-leverage "extension" move available and it costs nothing.
