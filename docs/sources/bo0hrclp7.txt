1) VERCEL
=====================================================

1.1 Functions / Fluid compute (docs last_updated 2026-08-24)
https://vercel.com/docs/functions/limitations
- Fluid compute is ON by default for new projects.
- Max duration (Node/Bun/Python, with Fluid): Hobby 300s default AND 300s maximum. Pro/Ent 300s default, 800s max (GA), 1800s extended max (beta, needs per-function config, not supported with Secure Compute/Static IPs).
- Memory: Hobby 2 GB / 1 vCPU (default = max). Pro/Ent 2 GB default, up to 4 GB / 2 vCPU.
- Concurrency: auto-scales to 30,000 (Hobby AND Pro), 100,000+ Ent.
- Bundle: 250 MB uncompressed; 500 MB Python; "Large functions" beta up to 5 GB (Node/Bun/Python, requires Fluid + Active CPU, env var VERCEL_SUPPORT_LARGE_FUNCTIONS=1).
- Request/response body: 4.5 MB hard cap (413 FUNCTION_PAYLOAD_TOO_LARGE). This matters: do not stream a 27-column x 94-industry table through a route handler body without paging.
- 1,024 file descriptors shared across concurrent executions — use the Neon HTTP driver, not a TCP pool.
- Default region iad1; multi-region is Pro+.

1.2 Fluid pricing (docs last_updated 2026-06-16)
https://vercel.com/docs/functions/usage-and-pricing
- Hobby included: 4 Active-CPU-hours, 360 GB-hrs provisioned memory, 1,000,000 invocations/month.
- Regional rates: iad1/pdx1/cle1 $0.128 per Active-CPU-hour and $0.0106 per GB-hr. Mumbai bom1 $0.140 / $0.0116. São Paulo gru1 $0.221 / $0.0183.
- Invocations on Pro: $0.60 per million.
- Billing model: Active CPU pauses during I/O (LLM calls, DB queries are effectively free CPU); provisioned memory bills for the whole instance lifetime. A valuation that waits on EDGAR is cheap; a valuation that does heavy numeric work is not.

1.3 Hobby plan (docs last_updated 2026-08-31) https://vercel.com/docs/plans/hobby
- 1,000,000 edge requests, 200 projects, 100 deployments/day, build 2 vCPU / 8 GB / 32 GB disk, runtime logs retained 1 hour, WAF 3 IP blocks + 3 custom rules.
- Hobby is restricted to non-commercial personal use (fair-use guidelines). A private research tool for himself is fine; the moment it is sold or shown to clients, it must move to Pro ($20/seat/mo).
- Exceeding a Hobby limit pauses that feature for 30 days (7 days for Web Analytics). There is no overage billing to absorb a mistake.

1.4 Cron (docs last_updated 2026-07-15) https://vercel.com/docs/cron-jobs/usage-and-pricing
- 100 cron jobs per project on ALL plans.
- Hobby: minimum interval ONCE PER DAY, precision ±59 minutes. `0 * * * *` or `*/30 * * * *` fail at deploy time with an explicit error.
- Pro/Ent: once per minute, per-minute precision.
- DIRECT CONSEQUENCE: the "monthly ERP / quarterly CRP watch" and "nightly refresh" fit Hobby. Anything intraday does not. And ±59 min jitter means the vintage stamp must come from the data source's own date, never from the cron fire time.

1.5 Vercel Queues — PUBLIC BETA (docs last_updated 2026-09-03 / pricing 2026-08-12)
https://vercel.com/docs/queues , https://vercel.com/docs/queues/pricing
- Durable append-only topics, fan-out to independent consumer groups, at-least-once, push mode (`handleCallback` + `experimentalTriggers: [{type:"queue/v2beta", topic:"..."}]` in vercel.json) and poll mode. SDKs: `@vercel/queue` (JS) and `vercel-queue` (Python).
- Billed per API operation (Send / Receive / Delete / Visibility change / Notify), metered in 4 KiB chunks — a 12 KiB message = 3 operations. Idempotency-key sends and max-concurrency push deliveries bill at 2x.
- Limits: TTL 60s–7 days (default 24h), delay up to 7 days, visibility timeout up to 60 min, 1–10 messages per receive, max message size 100 MB, unlimited topics and consumer groups, forced backoff after 32 retry attempts.

1.6 Vercel Workflows (docs last_updated 2026-09-04 / pricing 2026-06-16)
https://vercel.com/docs/workflows , https://vercel.com/docs/workflows/pricing
- Durable execution via the open-source Workflow SDK (workflow-sdk.dev): `'use workflow'` / `'use step'`. JS/TS AND Python (via the `vercel` Python SDK). Built on Queues + managed persistence.
- No max run duration, no max sleep duration. Per-run: 25,000 events, 10,000 steps, 50 MB max payload, 2 GB entity storage, 240s max replay time, 1,000 run creations/sec.
- Pricing: Workflow Events $0.02 per 1K (Hobby includes 50,000/month); Workflow Data Written $0.50/GB (Hobby includes 1 GB); Workflow Data Retained $0.50/GB-month and is NOT AVAILABLE ON HOBBY. Retention after run completion: Hobby 1 day, Pro 7 days, Ent 30 days.
- A normal step produces 3 events (step_created/started/completed), +1 per retry. A 5,000-company fan-out with 8 steps each ≈ 5,000 × (8×3 + overhead) ≈ 130K+ events/night ≈ 4M/month = ~$80/mo in events alone. Workflows is the wrong tool for wide cheap fan-out; it is the right tool for one long durable pipeline with sleeps.

1.7 Python runtime — GA (docs last_updated 2026-08-12)
https://vercel.com/docs/functions/runtimes/python
- Versions: 3.12 (default), 3.13, 3.14. uv supported zero-config.
- Framework presets for FastAPI / Flask / Django. Entrypoint = `app.py|index.py|server.py|main.py|wsgi.py|asgi.py` (also under `src/` or `app/`) exposing top-level `app` (ASGI/WSGI) or `application` (Django); or `[tool.vercel] entrypoint = "pkg.mod:app"`.
- Streaming on by default; bytecode precompiled into the bundle; 500 MB bundle (5 GB via Large Functions beta).
- To run Python AND Next.js in ONE project, use Vercel Services (each part builds independently, shared domain). This is the escape hatch if any part of the valuation engine is easier in Python — but the golden-test requirement argues for keeping the engine in one language.

1.8 AI SDK + OpenRouter vs AI Gateway
- AI SDK current major is v7 ("v7 (Latest)" on ai-sdk.dev). AI SDK for Python is in beta. There is no v6 line to target.
- `@openrouter/ai-sdk-provider` latest is 3.0.0: supports `ai@^7.0.0`, requires Node.js 22+, ESM-only, ~300+ models, reasoning via `providerOptions.openrouter.reasoning` or `extraBody`. It is a COMMUNITY provider — update timing follows the package maintainer, not Vercel's release train. (npm/@openrouter/ai-sdk-provider; github.com/OpenRouterTeam/ai-sdk-provider)
- Vercel AI Gateway is GA (docs last_updated 2026-09-07). Zero markup and zero platform fee on tokens, including BYOK. Endpoint `https://ai-gateway.vercel.sh/v1/chat/completions`; also speaks OpenAI Chat Completions, OpenAI Responses, and Anthropic Messages. Works from ANY infrastructure, not just Vercel; Vercel deployments can auth by OIDC instead of an API key. Free tier = a SUBSET of models plus a monthly free credit with lower per-model rate limits; buying credits moves you to paid and the monthly free credit stops. Add-on surcharges: Custom Reporting $0.075/1K tag writes + $5/1K report queries; team-wide provider allowlist $0.10/1K successful requests (per-request `only` filter is free); team-wide ZDR $0.10/1K requests (per-request ZDR free, Pro/Ent); Trace Drains $0.05/1K traces + $0.50/GB egress with no Pro allowance.
- OpenRouter fees (openrouter.ai/docs/faq): 5.5% + $0.80 minimum on Stripe credit purchases (5% crypto); BYOK 5% above a $25,000/month free allowance on pay-as-you-go; no per-request fee; prompts and completions are NOT logged by default (opt into logging for a 1% discount); free models limited to 50 requests/day, 1,000/day once you hold ≥$10 in credits.
- RECOMMENDATION: keep OpenRouter. The only measurable penalty is 5.5% on top-ups — on $25/month of models that is $1.38/month, which is noise against the $60–100 budget, and OpenRouter has the deepest open-weight catalog plus per-provider routing/privacy controls he wants. Mitigate the lock-in by putting model selection behind one module (`lib/models.ts` exporting `getModel(role)`), because both OpenRouter and AI Gateway are AI SDK v7 providers — swapping is a one-file change. Use AI Gateway only if he later wants keyless OIDC auth from Vercel or wants the free-tier credits for dev/CI.

3) PINECONE
=====================================================
https://www.pinecone.io/pricing/ , https://docs.pinecone.io/guides/assistant/pricing-and-limits

3.1 Index plans
- Starter (FREE): 2 GB storage, 2M write units/month, 1M read units/month, up to 5 indexes, 100 namespaces.
- Builder ($20/mo flat): 10 GB, 5M WU, 2M RU, 10 indexes/project, 1,000 namespaces.
- Standard ($50/mo minimum): storage $0.33/GB-month, WU $4–4.50 per million, RU $16–18 per million (region-dependent), 20 indexes/project, 100,000 namespaces.
- Enterprise ($500/mo min): WU $6–6.75/M, RU $24–27/M, 200 indexes.

3.2 Hard operation limits (https://docs.pinecone.io/reference/api/database-limits/operation-limits) — these apply on EVERY plan
- Upsert (pre-computed vectors): 1,000 records OR 2 MB per batch.
- Upsert with integrated embedding (`upsert_records`, text): MAX 96 RECORDS PER BATCH. 60,000 chunks ⇒ 625 batches. Plan the ingest as a queued fan-out, not one request.
- Record ID ≤512 chars. Dense vectors ≤20,000 dims. Filterable metadata ≤40 KB per record. `top_k` max 10,000; query response capped at 4 MB. Fetch by ID 1,000/request; fetch by metadata 10,000/response at 5 req/s per namespace. `$in`/`$nin` limited to 10,000 values each. Import: 1 TB / 100,000 files per job.

3.3 Integrated inference
- `createIndexForModel` / `create_index_for_model` with `embed: {model, fieldMap}` — Pinecone embeds on upsert AND on query, so you never run an embedding service. Hosted models include `llama-text-embed-v2` (multilingual, up to 2,048 input tokens, Matryoshka/dynamic output dims) and rerankers such as `cohere-rerank-3.5` via a separate rerank endpoint.
- Namespaces are the tenancy/partition primitive; metadata is the filter primitive.

3.4 Assistant
- Limits by plan: max assistants per project 5 (Starter) / 200 (Builder) / unlimited (Standard, Ent). File storage per org 1 GB / 3 GB / unlimited. Max file size 10 MB for .docx/.json/.md/.txt on every plan; .pdf 10 MB (Starter) / 50 MB (Builder) / 100 MB (Standard+). Chat input tokens/month 500K / 2M / unlimited; chat output 300K / 1M / unlimited. MAX INPUT TOKENS PER QUERY 64K ON EVERY PLAN. Monthly ingestion units 1K / 10K / unlimited (1 unit ≈ 400 tokens ≈ 300 words).
- Paid rates: chat input $8/M, chat output $15/M, CONTEXT RETRIEVAL $5/M, ingestion $0.0005/unit, assistant storage $3/GB/month. Multimodal PDF ingestion bills ≈2x.
- Supported file types: .docx, .json, .md, .pdf, .txt. File metadata: key/value pairs up to 16 KB per file, SET ONLY AT UPLOAD AND IMMUTABLE; supports filtering chat responses and listing files by filter.
- BYO-LLM: YES. The Context API (`/context`) takes `query`, `top_k` (default 16), `snippet_size` (default 2048 tokens) and returns `snippets[]` each with `type`, `content`, `score`, and a `reference` containing the file `{id, name, size, status}`, a `pages[]` array, and a `signed_url` valid for 1 hour. So citation = file name + page numbers + snippet + link, exactly the shape an "Ask Damodaran" answer needs, and you can hand those snippets straight to OpenRouter.

3.5 RECOMMENDATION for the ~60k-chunk corpus: INDEX WITH INTEGRATED EMBEDDING, NOT ASSISTANT.
Reasons, in order:
 a. Metadata. He needs `source_type ∈ {blog, packet, book, dataset, exam, transcript}`, `region`, `vintage`, `license_class`. An index gives 40 KB of FILTERABLE metadata per record and full `$eq/$in/$nin` filtering; Assistant gives 16 KB per FILE, immutable after upload, and filters at file granularity only.
 b. Chunking control. The corpus is already deduped and chunked; Assistant re-chunks opaquely and 1,477 unpunctuated ASR transcripts are exactly the case where you want your own chunker.
 c. Free-tier headroom. 60k chunks × 1024 dims × 4 bytes ≈ 245 MB + metadata — comfortably inside Starter's 2 GB. Assistant Starter caps at 1 GB of FILES and 500K chat input tokens/month, which one afternoon of testing would exhaust.
 d. Cost shape. Index reads are $16–18/M RU only above the free 1M; Assistant bills $5/M context tokens with no free ceiling once you leave Starter.
 e. He keeps the LLM on OpenRouter either way, but with an index he also keeps the retrieval prompt, the reranker choice, and the citation format.
Use Assistant only as a 1-day spike to see what "good" citations look like before building the index path.

4) MANAGED BACKGROUND JOBS / FAN-OUT
=====================================================
- Inngest (https://www.inngest.com/pricing): Hobby FREE = 50,000 executions/month, 5 concurrent steps, 500 MB span data, 500K events ingested, 3 users. Pro from $99/mo = 1M executions (PAYG to 20M), 100+ concurrent steps, 5 GB spans, 5M+ events, 15 users then $10/user, 7-day trace retention. CRITICAL COUNTING RULE: an execution = the run ITSELF PLUS each step. A function with 5 `step.run()` calls burns 6 executions per run. TS-first (also Python and Go SDKs), HTTP-invoked so it works fine against Vercel functions.
- Trigger.dev: Free = $0 with 20 CONCURRENT RUNS, 10 schedules, 1-day log retention, $5/month usage credits, unlimited tasks. Apache-2.0, self-hostable (Docker Compose / K8s), v4 GA. REAL PYTHON: the `pythonExtension` build extension + `@trigger.dev/python` run actual Python scripts inside the task container (pandas, Pillow, ML libs). `batchTrigger()` / `batchTriggerAndWait()` are built for fan-out. Best free-tier concurrency of the four.
- Upstash QStash (https://upstash.com/pricing/qstash): Free = 1,000 messages/DAY, 10 schedules, 1 MB max message, 50 GB bandwidth. PAYG $1 per 100K messages; fixed plans from $180/mo. Pure HTTP/REST so it calls Vercel functions with no SDK runtime. RETRIES ARE BILLED AS EXTRA MESSAGES (2 attempts = 2 messages). No Python execution — it only delivers HTTP.
- Vercel Cron + Queues (+ Workflows): cheapest integration (same project, same env vars, same logs) but Hobby cron is once-a-day only, Queues is beta, and Workflow events at $0.02/1K punish wide fan-out.
- RECOMMENDATION, staged:
  · 50 companies: Vercel Cron (daily, free) → one route handler loops 50 companies inside a single 300s invocation. No job platform at all. Zero extra cost, zero extra vendor.
  · 500–5,000 companies: Vercel Cron fires ONE handler that enqueues N jobs. Choose Inngest if you want step-level retries/memoization and concurrency throttling in TypeScript (5,000 × 9 executions = 45K/night = 1.35M/month → Pro $99). Choose QStash if the work is one HTTP call per company and you just need cheap durable fan-out (150K messages/month = $1.50). Choose Trigger.dev if any step must be Python.
  · Reserve Vercel Workflows for the single long durable pipeline (e.g. "refresh ERP → recompute CRP → revalue watchlist → notify") where sleeps and human-in-the-loop matter, not for the 5,000-way fan-out.

7) READING .XLS (BIFF8) AND .XLSX IN TYPESCRIPT
=====================================================
- SheetJS Community Edition: current version 0.20.3, Apache-2.0, distributed FROM cdn.sheetjs.com, NOT from npmjs. Install by tarball URL: `npm i https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`. SheetJS left the public npm registry; the `xlsx` package on npmjs is stuck at 0.18.5 (published ~4 years ago) and carries 2 unpatched high-severity advisories (prototype pollution, ReDoS) with no fix on that channel. NEVER `npm i xlsx`.
- ExcelJS: actively maintained, but XLSX/CSV ONLY — it cannot read legacy BIFF8 .xls at all. It is not an option for betaIndia/marginIndia/capexIndia/waccIndia .xls.
- BIFF8 is a Compound File Binary (OLE2) container; SheetJS CE is effectively the only mainstream JS library that parses it. The Python fallback is `pandas.read_excel(..., engine="xlrd")` (xlrd 2.x reads .xls only).
- OUTSOURCED ONE-OFF CONVERSION (275 .xls → JSON → Neon), best to worst:
  1. GITHUB ACTION (recommended). Public repos get unlimited free minutes on standard GitHub-hosted runners; private repos on the Free plan get 2,000 minutes/month + 500 MB storage shared with Packages. A `workflow_dispatch` job checks out the raw files (or pulls them from Vercel Blob), runs the SheetJS CE converter, writes JSON artifacts, and `COPY`s into Neon using `NEON_API_KEY`/`NEON_PROJECT_ID`. The run log IS the provenance record — commit the converter, the input checksums, and the output row counts. Deterministic, re-runnable, versioned, $0.
  2. Trigger.dev task with the Python extension, if he prefers pandas.
  3. Vercel Sandbox (Firecracker microVM, native Python) invoked once — fine, but 45-min Hobby session cap and it is a worse audit trail than a committed Action.
  4. A Vercel route handler doing it inline — worst: 4.5 MB body cap, 300s Hobby duration, 250 MB bundle, and no artifact history.
- Whichever path: stamp every emitted row with `source_file`, `sha256`, `vintage_date`, `retrieved_at`, `license_class`, and store the raw .xls in Vercel Blob so the conversion is reproducible from the original bytes.

8.3 SINGLE POINTS OF COST (where the bill actually explodes)
  1. LLM tokens if you call a model PER COMPANY per night. Fix: LLM only on user request or on material change (delta in value/share > threshold); the valuation itself is arithmetic and needs no model.
  2. Langfuse units if you log every step of every batch run. Fix: sample the batch at 10%, log 100% of interactive chat.
  3. Neon CU-hours if the nightly job holds a warm compute for hours. Fix: one batched window, let scale-to-zero fire; never disable scale-to-zero on Launch.
  4. Pinecone READ units if the UI queries per keystroke. Fix: debounce, cache query embeddings, cap top_k (default 16 snippets is plenty).
  5. Pinecone WRITE units on re-embedding. A full 60k-chunk rebuild is a large chunk of the 2M free WU. Fix: content-hash each chunk, upsert only changed ids.
  6. Vercel's $150/month Advanced Deployment Protection if he tries to password-protect production. Fix: app-level auth (§5).
  7. Inngest's run+step execution counting. A 12-step workflow costs 13 executions; collapse steps that cannot fail independently.

WHAT IS STATELESS (and therefore scales horizontally for free)
  · Every Route Handler and Server Component (Vercel autoscales to 30,000 concurrent on Hobby AND Pro).
  · The valuation engine — pure function, no shared state, embarrassingly parallel across companies.
  · Pinecone queries — serverless, scale with read units not with instances.
  · Queue consumers — add consumer groups without coordination.

WHAT DOES NOT SCALE HORIZONTALLY
  · Neon's primary write endpoint. Batch writes; use COPY; never one INSERT per fact. Read replicas exist only on Scale.
  · The nightly batch WINDOW — 5,000 companies against SEC/EODHD rate limits is a throughput problem, not a compute problem. Concurrency must be throttled at the job layer (Inngest concurrency keys / QStash max-concurrency), not by adding functions.
  · Anything holding a TCP connection pool inside a serverless function (1,024 shared file descriptors). Use `drizzle-orm/neon-http` against the POOLED endpoint.
  · Vercel Hobby cron granularity (once/day) — this is a plan wall, not a scaling wall.

ON THE UI SCALABILITY DOUBT (company picker → backend → valuation tabs + chat)
  The UI shape is fine; what does not scale is computing on demand inside the request. Split it: the picker reads a PRE-COMPUTED `valuation_run` row (a cached read, milliseconds, scales to 30K concurrent); a "recompute" button enqueues a job and streams progress. The chat tab is independent — it touches Pinecone + OpenRouter and never the engine. Scaling from 50 to 5,000 companies then changes only the job layer and Neon's compute size; not one line of UI.

## 2) Legitimate uses inside the valuation workflow

- **Manual clipping.** You read the article; you type *your own sentence* of what changed into a `narrative_note` row with `source_url`, `source_name="Bloomberg"`, `published_at`, `retrieved_at`, `license_class="proprietary_personal"`. Store **URL + headline + your paraphrase**, never article body text. Cap any verbatim quote at a sentence fragment. This is note-taking, not database construction.
- **Newsletters via your Gmail connector.** Bloomberg *sends* the email to you; reading your own mailbox is a Gmail operation and does not touch "the Service" with a scraper. This is the cleanest automated-ish path. The content restrictions still ride along: extract link + headline + date into notes, do not persist full bodies, do not redistribute. For India equities the two that matter are **India Edition** and **Markets Daily India**; add **Markets Daily** and **Money Stuff** for context. (Deep-linking automation into newsletters is a grey zone — keep it read-only and personal.)
- **Reader-mode / summaries for personal use.** Fine as ephemeral, in-session output. Do not cache the summary as a corpus chunk retrievable by RAG — that is the database clause again.
- **Hard rule to encode:** `license_class="proprietary_personal"` rows are **excluded from the RAG index and from any shared/published artefact**; they appear only in your own narrative-notes UI.

## 4) Where news belongs: story → numbers

News never sets value. It moves **one named input**, and the input moves value through the existing fcffsimpleginzu logic — so every narrative note must name its driver:

| News type | Legitimate input moved |
|---|---|
| New store/format rollout, price hikes, TAM, market share | `revenue_growth_yr1..5` |
| Input costs, discounting, competitive entry, mix shift | `operating_margin_target`, `years_to_converge` |
| Capex plan, acquisition, working-capital change | `sales_to_capital` (remember the 1-yr lag on ΔRevenue) |
| Debt raise, rating change, interest-coverage shift | synthetic rating → cost of debt → WACC |
| Sovereign/regulatory, India CRP/ERP revision | `country_risk_premium`, `ERP` (India Jan-2026: Baa3, spread 1.87%, ERP 7.08%, CRP 2.85%) |
| Litigation, covenant breach, going-concern | failure probability / distress proceeds |

**Audit schema (`narrative_notes` in Neon, not CSV):** `id, ticker, exchange, as_of_date, driver (enum above), direction (+/-/0), old_value, new_value, rationale_text (your words), source_url, source_name, license_class, published_at, retrieved_at, vintage_id, confidence, superseded_by`. Rules: (a) a valuation run is reproducible only if every non-default input has ≥1 note; (b) `vintage_id` pins which rf/ERP snapshot was live (the 2026 file carries 3.95/4.58/4.75% rf and 4.20/4.23/4.46% ERP — always stamp); (c) the **Almarai golden test at 1e-6 must still pass with all notes applied as zero-deltas**, proving the narrative layer is additive and never mutates the engine; (d) notes render as "Story → Input → Δ → Value impact" with no buy/sell language.

 - India-specific assets: Market Snapshot module, 'India Edition' newsletter (Menaka Doshi), 'Markets Daily India' pre-open brief, 'Emerging' podcast, India editions of Businessweek/Markets from Oct 2026.
 - INR payment via local cards is live; UPI support added Sept 2026. Bloomberg does not publish a static INR rate card - price is geo-set at checkout, so the exact INR figure must be read off the user's own billing page.
 - Consumer tiers are Digital (~USD 19.99/mo, ~199/yr) and All Access (~USD 34.99/mo, ~415/yr), plus corporate and student.
 - Not included at any consumer price: Bloomberg Terminal, B-PIPE, Data License/OneData, SAPI, BLPAPI SDKs - all enterprise Bloomberg Professional Services products.
 - There is no official public API and no official RSS for bloomberg.com content; email newsletters are the only sanctioned push channel.
 - Bloomberg ToS Sec.3 verbatim: 'You shall not use or attempt to use any "scraper," "robot," "bot," "spider," "data mining," "computer code," or any other automate device, program, tool, algorithm, process or methodology to access, acquire, copy, or monitor any portion of the Service'.
 - Bloomberg ToS Sec.3 verbatim: 'The Service and the information contained therein may not be used to construct a database of any kind. Nor may the Service be stored (in its entirety or in any part) in databases for access by you or any third party' - this is the binding clause that keeps Bloomberg out of the RAG index.
 - Bloomberg ToS Sec.3 grants: 'you may download material from the Service and/or make one print copy for your own personal, noncommercial use' and forbids recirculation/redistribution without prior written consent.
 - Reading one's own Bloomberg newsletters via the Gmail connector does not invoke a scraper against 'the Service' and is the cleanest semi-automated path; content restrictions (no full-body storage, no redistribution) still apply.
 - Artificial Analysis launched its Search Index on 18 Aug 2026: Parallel advanced 75 @ $0.084/task, Exa auto 74 @ $0.127, Firecrawl 73 @ $0.075 (cheapest but slowest at 55s), Parallel turbo 67 @ $0.060, Tavily basic 66 @ $0.193, Brave 65 @ $0.146.
 - Search API pricing Aug 2026: Exa 1,000 free searches/mo then ~$1.50-7 per 1k; Tavily 1,000 free/mo then $0.008/credit, plans from $30/mo; Firecrawl free tier then $99/mo for 100k credits ($83/mo annual); Parallel has no free tier.
 - EODHD: Fundamentals Data Feed $59.99/mo; Financial News API is an add-on bundled into ALL-IN-ONE at $99.99/mo; free tier is 20 calls/day with 1 year of history; each news request costs 5 API calls plus 5 per ticker; standard plans are personal-use only.
 - Finnhub news-sentiment is US-companies-only, disqualifying it for Indian coverage; Marketaux is free to 100 req/day covering 200k+ entities across 80+ markets; GDELT is free and global but weakly ticker-tagged; Google News RSS is free but unofficial with no storage licence.
