### Rate limits & fees
- `:free` models: **20 req/min always**. **50 req/day** if you have never bought credits; **1,000 req/day** once you have bought ≥$10 lifetime.
- Paid models: no platform-level request cap.
- **Credit purchase fee: 5.5% via Stripe ($0.80 minimum), 5% via USDC.** No markup on inference itself — you pay provider list price.
- BYOK: first 1,000,000 BYOK requests/month free of platform fee; PAYG includes $25,000/mo of list-price inference before the 5% BYOK fee bites. Irrelevant at your scale.

**Free tier is unusable for your bulk job.** 1,000 req/day × 30 days = 30,000 requests/month. Punctuating 1,477 transcripts + tagging 60k chunks needs ~60k+ requests. You will pay. The good news is §6 shows it costs about the same as one pizza.

**Storage:** 60,000 chunks × 1024 dims × 4 bytes = **245 MB** raw vectors. With metadata (source, license_class, vintage, url, doc_type) call it 400–600 MB. **Fits inside Pinecone Starter's free 2 GB.** 60k upserts is 3% of Starter's 2M free write units. A top_k=50 query costs single-digit read units; 1M free RU/month covers thousands of questions.

### 5d. RECOMMENDED RETRIEVAL STACK — $0/month

> **Embedding: `voyage-context-4`** (1 vendor call, $0.12/M, 200M free tokens → build is free, 32k input so an 800-token chunk is never truncated, and it embeds each chunk *aware of its neighbours* — which is exactly the fix for unpunctuated ASR transcript chunks and mid-thread blog paragraphs that are meaningless standalone).
>
> **Sparse companion: `pinecone-sparse-english-v0`** ($0.08/M) in a hybrid index. Non-negotiable for this corpus: dense embeddings are bad at exact-token recall of "sales-to-capital ratio", "Almarai", "Baa3", "fcffsimpleginzu", ticker symbols and specific years. Hybrid dense+sparse is the difference between finding the 2019 India ERP and hallucinating it.
>
> **Reranker: Voyage `rerank-3`** ($0.05/M, 200M free). At 50 candidates × 800 tokens = 40k tokens/query → **$0.002/query**, and free until you have run ~5,000 queries. Pinecone's `cohere-rerank-4-fast` is the same $0.002/request but Starter only includes 500 rerank calls/month and only for bge.
>
> **Vector DB: Pinecone Starter (free)**, upserting your own vectors. Upgrade to Builder ($20) only when storage exceeds 2 GB or read units exceed 1M/mo.
>
> **Why not Pinecone integrated inference?** It is one fewer vendor and genuinely simpler for a beginner — but `llama-text-embed-v2` caps at 2,048 input tokens, and the 5M tok/mo Starter cap makes a 30M-token build take six months. If you want the single-vendor simplicity, budget one month of Standard ($50 + $4.80 usage) to do the build, then drop back. **The Voyage path costs $0 and gives a better model. Take it.**
>
> **Do not use `multilingual-e5-large`** — its 507-token input limit silently truncates your 800-token chunks. That is a correctness bug wearing a price tag.

**Largest context windows purchasable today (verified live on OpenRouter):**

| Model | Context | $/1M in |
|---|---|---|
| **x-ai/grok-4.20** | **2,000,000** | 1.25 |
| z-ai/glm-5.3 / glm-5.3-flash | 1,310,720 | 1.40 / 0.15 |

| openai/gpt-6-astra | 1,050,000 | 10.00 |
| anthropic/claude-fable-5.1, opus-5 | 1,000,000 | 10.00 / 5.00 |

**Your corpus is 30,000,000 tokens. The largest window on earth is 2,000,000. The corpus is 15x larger than the biggest context window that exists. Long-context is not an option — it is arithmetically impossible in a single call.**

### Cost per question, three strategies

Assumptions: RAG = 8 chunks × 800 tok + 1,500 tok system prompt + 100 tok question = **8,000 input**, 700 output.

| Strategy | Input tokens | Model | Cost / question |
|---|---|---|---|
| **RAG, 8 chunks** | 8,000 | GLM-5.3-Flash | 8,000×$0.15/M + 700×$0.50/M = **$0.00155** |
| RAG, 8 chunks | 8,000 | GLM-5.3 | $0.0112 + $0.0031 = **$0.0143** |
| RAG, 8 chunks | 8,000 | Claude Fable 5.1 | $0.080 + $0.035 = **$0.115** |
| **Stuff 200k (one lecture packet)** | 200,000 | GLM-5.3-Flash | $0.030 + $0.00035 = **$0.0304** (cached re-read: $0.0060) |
| Stuff 200k | 200,000 | GLM-5.3 | $0.280 + $0.0031 = **$0.283** (cached: $0.055) |
| Stuff 200k | 200,000 | Claude Fable 5.1 | $2.000 + $0.035 = **$2.035** (cached: $0.085) |
| **Stuff whole corpus (15 calls + synthesis)** | 30,000,000 | GLM-5.3-Flash | **$4.50** (cached: $0.90) |
| Stuff whole corpus | 30,000,000 | Grok 4.20 @ 2M ctx | **$37.50** |
| Stuff whole corpus | 30,000,000 | Claude Fable 5.1 | **$300.00** |

### The ratios

- **200k-stuff vs 8-chunk RAG, same model: 19.6x more expensive** ($0.0304 / $0.00155)
- **Full-corpus vs RAG: 3,750x the tokens ≈ 2,900x the cost** ($4.50 / $0.00155)
- **One full-corpus question on Claude Fable 5.1 ($300) costs 62x more than building your entire Pinecone index forever ($4.80 on Pinecone, $0 on Voyage).**

### VERDICT: RAG pays for itself on question #1.

The index build is **$0–4.80 one-time**. A single naive full-corpus question is **$4.50–$300**. Break-even is *literally the first question*.

### When long-context beats RAG — and you should use both

| Situation | Use | Why |
|---|---|---|
| "Summarise the 2026 valuation lecture packet" (single 150k-token doc) | **Long context** | Retrieval fragments an argument that only makes sense whole. $0.03 on GLM-5.3-Flash. |
| "Walk me through the cost-of-capital worksheet end to end" (one xlsx sheet) | **Long context** | Ditto. |
| "Reconcile chapter 4 of the 2023 book against the 2019 lecture" (2 docs, 300k) | **Long context** | Cross-document reasoning inside one window. |
| "What is Damodaran's India ERP and when did he change it?" | **RAG** | Needle across 609 posts × 14 years. |
| "Show every time he discussed synthetic ratings" | **RAG** | 1,477 transcripts; needles are everywhere. |
| "Cite him on terminal growth ≤ risk-free rate" | **RAG + rerank** | You need the *citation*, not a summary. |
| Anything spanning >2M tokens | **RAG only** | Physically impossible otherwise. |

**Where long context cannot help you at all:**
1. **Citations.** You need `source`, `license_class` and `vintage` on every fact. A 2M-token stuff returns a paragraph with no verifiable pointer. RAG returns chunk IDs you can render as footnotes. This is a hard requirement from your non-negotiables, and it alone decides the question.
2. **Latency.** Prefilling 200k tokens takes seconds; 8k is instant. Your Ask-Damodaran chat tab has to feel like a chat.
3. **Vintage stamping.** RAG lets you filter `WHERE vintage = '2026-01'` *before* the model sees anything. Long-context makes the model do date arithmetic on conflicting snapshots — which is precisely how you'd end up mixing the 3.95%, 4.58% and 4.75% risk-free rates in one answer.
4. **Scalability (your question #7).** RAG cost is **O(1) in corpus size** — 8 chunks whether the corpus is 30M or 300M tokens. Long-context is **O(n)**. Adding EODHD filings, 10-Ks and future blog years multiplies a long-context bill and changes nothing about a RAG bill. *That* is the scaling answer for your UI.

**Architecture: hybrid router.** Classify the question first. Single-document → fetch the whole doc, stuff it (cheap on GLM-5.3-Flash at $0.15/M). Corpus-wide → hybrid retrieve 50 → rerank → top 8 → answer with citations. Same model behind both; only the retrieval path differs.

## 3. OpenRouter as provider — exact wiring

- **Env var: `OPENROUTER_API_KEY`.** `export OPENROUTER_API_KEY=...; pi`
- Or OAuth: `/login openrouter` → "Sign in with OpenRouter" → PKCE flow, mints a user-controlled key billed from your OpenRouter credits, stored in `~/.pi/agent/auth.json`. On headless/SSH you can paste the final redirect URL or the auth code into the prompt.
- **Credential resolution order:** `--api-key` flag → `auth.json` → `OPENROUTER_API_KEY` env → custom provider key in `models.json`.
- Provider is **built in**, not custom. Source `packages/ai/src/providers/openrouter.ts`: `id: "openrouter"`, `baseUrl: "https://openrouter.ai/api/v1"`, two APIs supported — `anthropic-messages` **and** `openai-completions` — and a **bundled model catalog** `OPENROUTER_MODELS` auto-generated from `packages/ai/src/providers/data/openrouter.json` (regenerated by `npm run generate-models` per release). So open-weight OpenRouter models appear in `/model` with pricing already attached; you do not have to hand-write them.
- Select: `pi --provider openrouter --model <model-id>`, or in-session `/model` (Ctrl+L). **Ctrl+S inside the `/model` picker saves it as the startup default.** Persist in settings:
```json
{ "defaultProvider": "openrouter", "defaultModel": "<openrouter-model-id>", "defaultThinkingLevel": "medium" }
```
- `Ctrl+P` cycles a short-list; define it with `enabledModels` (settings) / `--models <patterns>` / `/scoped-models`.
- **Per-model cost:** `~/.pi/agent/models.json` accepts per-million-token pricing and tiers:
```json
{ "providers": { "openrouter": { "baseUrl": "https://openrouter.ai/api/v1", "api": "openai-completions", "models": [
  { "id": "some/model", "cost": { "input": 5, "output": 30, "cacheRead": 0.5, "cacheWrite": 6.25 },
    "tiers": [ { "inputTokensAbove": 272000, "input": 10, "output": 45 } ] } ] } } }
```
`models.json` is **re-read every time you open `/model`** — live edits, no restart. (docs/providers.md, docs/models.md)

- **`@tintinweb/pi-subagents`** — Claude-Code-style sub-agents + workflow orchestration, parallel background agents with queuing, live widget, fleet view, mid-run steering.
- **`@d3ara1n/pi-subagent`**, **mjakl/pi-subagent** — lighter role-based variants.
- **Official example** `examples/extensions/subagent/`: each subagent is a **separate `pi` process** with isolated context; agents are `.md` files in `~/.pi/agent/agents/` or `.pi/agents/`; ships `scout.md`, `planner.md`, `reviewer.md`, `worker.md` and workflow prompt templates `implement.md` (scout→planner→worker), `scout-and-plan.md`, `implement-and-review.md`. Tracks turns/tokens/cost per agent; Ctrl+C propagates.

## 10. Sessions — persistence, branching, sharing

- Auto-saved **JSONL** in `~/.pi/agent/sessions/`, bucketed by cwd, **tree-structured** (not linear). Override with `--session-dir` > `PI_CODING_AGENT_SESSION_DIR` > `sessionDir` setting.
- `pi -c` continue last · `pi -r` resume picker · `pi --session <path|id>` · `pi --fork <path|id>` · `pi --name "..."` · `pi --no-session` (ephemeral).
- In-session: `/session` (file, ID, messages, tokens, **cost**), `/name`, `/resume`, `/tree` (arrow-key navigation of branches, Ctrl+O filter; selecting a user message puts it back in the editor), `/fork`, `/clone`, `/new`, `/export [file]` (HTML or JSONL), `/import <file>`, **`/share` → uploads as a private GitHub gist with a shareable HTML link** (base URL configurable via `PI_SHARE_VIEWER_URL`).
- Bash/powershell tools receive `PI_SESSION_ID`, `PI_SESSION_FILE`, `PI_PROVIDER`, `PI_MODEL`, `PI_REASONING_LEVEL` in env — useful for stamping vintage/provenance from inside tool scripts.

## 11. MCP — NOT native; via extension

pi.dev lists MCP among **deliberate omissions** ("Pi intentionally excludes: MCP integration, sub-agents, permission popups, plan mode, built-in to-dos, and background bash"). There is an open tracking issue `earendil-works/pi#563` "feat(coding-agent): Add MCP extension example".

**The de-facto answer: `pi install npm:pi-mcp-adapter`** (nicobailon/pi-mcp-adapter). It auto-detects standard MCP config files — `~/.config/mcp/mcp.json` (global) and `.mcp.json` (project):
```json
{ "mcpServers": { "chrome-devtools": { "command": "npx", "args": ["-y", "chrome-devtools-mcp@1.6.0"] } } }
```
Design: instead of injecting every MCP tool schema up-front (10k+ tokens), it exposes **one proxy tool (~200 tokens)** and discovers tools on demand. Status: heavily used — one Sept-2026 review cites **197,718 weekly downloads** and a 13,700→~200 token reduction. Sub-agents can request direct MCP tools via `mcp:server-name` frontmatter. Bright Data published a "Using Bright Data's Web MCP with Pi Agent" walkthrough, so third-party MCP servers are known to work through it.

## 12. Permission / sandbox on macOS without Docker

Official position (docs/security.md): **"Pi does not include a built-in sandbox."** Built-in tools read/write/edit files and run shell commands with the permissions of the `pi` process. No permission popups. Prompt injection from repo files/build output is called "expected local-agent risk" that pi cannot prevent. The only built-in gate is **project trust** — whether project-local `.pi/settings.json`, `.pi/extensions|skills|prompts|themes`, SYSTEM.md files and ancestor `.agents/skills` are loaded. Decisions stored in `~/.pi/agent/trust.json`; `defaultProjectTrust: "ask"|"always"|"never"`; flags `-a/--approve`, `-na/--no-approve`; `/trust` to save.

docs/containerization.md recommends Gondolin (QEMU micro-VM, needs Node ≥23.6 + QEMU), plain Docker, NVIDIA OpenShell, or Docker Sandboxes — **it says nothing about macOS/seatbelt.**

**But the repo ships the macOS answer as an example extension:** `examples/extensions/sandbox/` depends on `@anthropic-ai/sandbox-runtime@0.0.26` and its header states: *"Uses @anthropic-ai/sandbox-runtime to enforce filesystem and network restrictions on bash commands at the OS level (**sandbox-exec on macOS**, bubblewrap on Linux)."* It overrides the built-in `bash` tool. Config merges `~/.pi/agent/extensions/sandbox.json` (global) and `<cwd>/.pi/sandbox.json` (project):
```json
{ "enabled": true,
  "network":    { "allowedDomains": ["github.com", "*.github.com"], "deniedDomains": [] },
  "filesystem": { "denyRead": ["~/.ssh", "~/.aws"], "allowWrite": [".", "/tmp"], "denyWrite": [".env"] } }
```
Defaults already deny-read `~/.ssh ~/.aws ~/.gnupg`, deny-write `.env .env.* *.pem *.key`, allow-write `.` and `/tmp`, and allow-list npm/pypi/github domains. Usage: `pi -e ./sandbox`, `--no-sandbox` to disable, `/sandbox` to inspect. Setup = copy the dir to `~/.pi/agent/extensions/` and `npm install` inside it. **Linux needs bubblewrap/socat/ripgrep; macOS needs none of that.** This is the no-Docker macOS story.

**Beginner recommendation:** install three layers — `sandbox/` (OS-level, macOS-native), `permission-gate.ts` (confirm before `rm -rf`, `sudo`, …), `protected-paths.ts` (block writes to `.env`, `.git/`, `node_modules/`). Optionally `dirty-repo-guard.ts` + `git-checkpoint.ts` so every turn is recoverable. Community alternatives exist (`@gotgenes/pi-permission-system`, `cc-safety-net`, `@trim21/personal-pi-extensions` with bwrap) but the in-repo examples are the ones maintained alongside the core.

## 13. AGENTS.md / CLAUDE.md project instructions

Loaded and concatenated at startup, in this order: `~/.pi/agent/AGENTS.md` (global) → each parent directory ascending → current directory. **`CLAUDE.md` is accepted as an alternative filename.** If a directory contains `AGENTS.override.md`, pi loads that *instead of* the standard files for that directory. System-prompt control: `.pi/SYSTEM.md` (project replacement) > `~/.pi/agent/SYSTEM.md` (global replacement); `APPEND_SYSTEM.md` appends rather than replaces. Disable everything with `--no-context-files` / `-nc`. Also `examples/extensions/claude-rules.ts` scans a `.claude/rules/` folder — so an existing Claude-Code repo layout is largely portable.

## 14. Context management

- **Auto-compaction** trigger: `contextTokens > contextWindow - reserveTokens`, checked after tool results are appended and before the next assistant response. Walks backward to keep `keepRecentTokens`, LLM-summarises the cut region (folding in any prior summary), appends a summary entry plus `firstKeptEntryId`, and rebuilds context as summary + recent messages.
- Defaults: `reserveTokens: 16384`, `keepRecentTokens: 20000`, `compaction.enabled: true`, plus `compaction.modelOverrides` per model. Same block available in project `.pi/settings.json`.
- Manual: **`/compact [instructions]`**. Programmatic: `ctx.compact()`; events `session_before_compact`, `session_compact`, `session_compact_failed`; examples `custom-compaction.ts`, `trigger-compact.ts` (fires at >100k tokens).
- **There is no `/clear`.** The equivalents are **`/new`** (fresh conversation), `/fork` / `/clone`, and `--no-session`. `branchSummary.reserveTokens` (16384) governs summarisation when you jump branches in `/tree`.

## 15. Cost transparency

- The **TUI footer shows token/cache usage, cost (USD), context usage, and current model, live.**
- **`/session`** prints session file, ID, message count, tokens and **cost**; totals include assistant responses, tool-reported usage, and summary generation.
- Pricing comes from the bundled per-provider catalogs (`cost.input/output/cacheRead/cacheWrite` per million tokens, plus `tiers`) and anything you add in `models.json`. OpenRouter models arrive with pricing from the generated `data/openrouter.json`.
- **There is no `/usage` command** — cost is footer + `/session` + (in CI) the action's `cost` output. A Sept-2026 review flags "uneven cost visibility between modes" as a real gap: the footer is TUI-only, so in `-p`/`--mode json` you must read usage out of the event stream yourself. `showCacheMissNotices` surfaces cache diagnostics. `PI_CACHE_RETENTION=long` enables extended provider prompt caching.

## 16. Headless / CI — YES, three ways

1. **Print mode:** `pi -p "prompt"` (alias `--print`). Pipes work: `cat file.md | pi -p "summarize this"`.
2. **JSON event stream:** `pi --mode json "prompt"` — one JSON object per line; starts with a session header (version, id, timestamp, cwd), then events. `message_update` records are **delta-only** (fields `contentIndex`, `delta`, cumulative `usage`) to keep the stream linear-sized. Filter with jq:
   `pi --mode json "List files" 2>/dev/null | jq -c 'select(.type == "message_end")'`
   Also `--mode rpc` (stdin/stdout JSONL) for driving pi from a non-Node process, and the SDK (`createAgentSession` + `SessionManager.inMemory()` + `session.subscribe`) for embedding.
3. **A published GitHub Action exists: `shaftoe/pi-coding-agent-action@v2`** (v2.28.0 on the Marketplace as "pi GitHub Action"; works on GitHub, Codeberg and self-hosted Forgejo). Inputs: `github_token` (required), `provider` (required), `model` (required), `token` (provider API key), `prompt`, `pr_number`. **Outputs: `response`, `success`, `cost` (USD), `duration_seconds`, `share_url`.** It bundles pi SDK 0.85.1 plus GitHub tools for PR review, diffs, CI status, thread retrieval, and loads your skills/extensions/AGENTS.md as the CLI would.
```yaml
on: { issue_comment: { types: [created] } }
jobs:
  pi-agent:
    if: startsWith(github.event.comment.body, '/pi ')
    runs-on: ubuntu-latest
    steps:
      - uses: actions/setup-node@v6
      - uses: shaftoe/pi-coding-agent-action@v2
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          provider: openrouter
          model: <openrouter-model-id>
          token: ${{ secrets.OPENROUTER_API_KEY }}
```
Non-interactive trust: `-a/--approve` or `-na/--no-approve`; without a flag, non-interactive runs fall back to `defaultProjectTrust`. **In CI you must pass `--approve` (or set `defaultProjectTrust`) or project `.pi/` resources are silently ignored.** Use `PI_OFFLINE` / `PI_SKIP_VERSION_CHECK` to kill startup network chatter in runners.

## 17. Known rough edges reported in 2026

- **"Day one feels sparse to the point of feeling broken"** until you install extensions; the DIY assembly burden is the #1 bounce reason ("it doesn't finish the job the way Claude Code or OpenCode do"). Monorepo/package customisation model feels heavier than single-binary competitors. (vibecodinghub / mejba / adipod round-ups, 2026)
- **Stdin pipe handling can hang ~180 s without redirection** (use `< /dev/null` in scripts). (heyuan110, 2026-09-06)
- **Auto-discovered skills silently inflate context** — 48 skills = +9,400 tokens.
- **~449 MB on-disk footprint and unrequested binary downloads (`fd`, `ripgrep`)** on first run; npm tarball itself is 21.9 MB.
- **XDG non-compliance on Linux** (`~/.pi` not `~/.config/pi`) — a live community complaint; irrelevant to you on macOS.
- **Repetitive provider-configuration warning spam**; **uneven cost visibility between modes**.
- **Extension guards are advisory, not a security boundary** — a 40-line `tool_call` guard was circumvented by a motivated model reframing the request. Only the OS sandbox is a real boundary.
- **No observability/dashboard layer and no permission layer by design** ("primitives, not features"); containers/sandbox are the intended boundary.
- Measured vs OpenCode on a 30-task set: **pi 21/30 (70%) at $1.64 vs OpenCode 19/30 (63%) at $2.25, pi slower at the median (363 s vs 281 s)**. Vs Claude Code on a small invoice project: pi baseline context **1,358 tokens vs Claude Code 31,012** (~20x), and per-task cost $0.10/$0.11/$0.31 (pi) vs $0.61/$0.77/$1.16 (Claude Code), same functional outcomes, speed roughly a wash.
- Armin Ronacher (2026-01-31) praises the short system prompt, four tools (read/write/edit/bash), extension-driven persistent state, and the session tree; his structural criticism of MCP generally is that tools must be loaded at session start, which is exactly the gap `pi-mcp-adapter` closes.
- A production-focused fork, **oh-my-pi**, exists (adds LSP, DAP, hashline edits) if you later want more batteries.

## D. Extension idea: `value_company` tool hitting the deployed API

`.pi/extensions/value-company/index.ts`:
```typescript
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";
import { Type } from "typebox";

export default function (pi: ExtensionAPI) {
  pi.registerTool({
    name: "value_company",
    label: "Value company",
    description: "Run the deployed FCFF valuation API for a ticker and return value/share, WACC, terminal assumptions, and the vintage stamp.",
    promptSnippet: "value_company(ticker, market, vintage?) → intrinsic value from the deployed engine",
    promptGuidelines: [
      "Use value_company instead of re-implementing DCF math in a scratch script.",
      "Always report the returned vintage_id and license_class alongside the number.",
      "Never convert the output into a buy/sell recommendation."
    ],
    parameters: Type.Object({
      ticker: Type.String(),
      market: Type.Union([Type.Literal("US"), Type.Literal("IN")]),
      vintage: Type.Optional(Type.String({ description: "vintage id; omit for latest" })),
      scenario: Type.Optional(Type.String())
    }),
    async execute(_id, params, signal) {
      const base = process.env.VALUATION_API_URL ?? "https://valuation.vercel.app";
      const res = await fetch(`${base}/api/value`, {
        method: "POST",
        headers: { "content-type": "application/json", authorization: `Bearer ${process.env.VALUATION_API_TOKEN}` },
        body: JSON.stringify(params),
        signal
      });
      if (!res.ok) return { content: [{ type: "text", text: `API ${res.status}: ${await res.text()}` }], details: {} };
      const d = await res.json();
      return {
        content: [{ type: "text", text:
          `${d.ticker} (${d.market})\nvalue/share ${d.valuePerShare}\nprice ${d.price}\nWACC ${d.wacc} → terminal ${d.terminalWacc}\nrating ${d.syntheticRating}\nvintage ${d.vintageId}  sources ${d.sources.length}  license ${d.licenseClass}` }],
        details: d
      };
    }
  });
}
```
Why an extension and not an MCP server: it is 40 lines, zero extra process, zero extra token overhead, and it lives in the repo next to the API it calls. Add `pi-mcp-adapter` only when you want *third-party* servers (Neon, Pinecone, browser) — and note the sandbox's `allowedDomains` must then include those hosts.

Second extension worth adding early: a `tool_call` listener that **refuses any write under `tests/golden/`** and any diff that changes the string `7.187840270062114`. Belt on top of `denyWrite`.

# « 6-LINE COMPARISON — only where it changes a decision »

1. **Sandbox on macOS without Docker:** Claude Code ships permission prompts + its own sandbox by default; pi ships none and you must install `examples/extensions/sandbox` (`@anthropic-ai/sandbox-runtime` → `sandbox-exec`) plus `permission-gate.ts`; OpenCode sits between. → Decision: budget one setup evening for pi's safety layer, or you are running an agent unsandboxed on a machine with your OpenRouter key in the environment.
2. **Model freedom:** pi has OpenRouter as a first-class built-in provider (OAuth + bundled priced catalog + mid-session `/model`); Claude Code is Anthropic-first and does not do arbitrary open-weight models; OpenCode is also provider-agnostic. → Decision: your "OpenRouter + open-weight, artificialanalysis-driven" constraint eliminates Claude Code as the harness and leaves pi vs OpenCode.
3. **Context/token economics:** measured baseline context pi 1,358 tokens vs Claude Code 31,012 (~20x), per-task cost ~5x cheaper on a small project; vs OpenCode pi scored 21/30 at $1.64 vs 19/30 at $2.25 but was slower (363 s vs 281 s median). → Decision: pi is the cheapest per task, which matters at your $60–100/mo ceiling; accept slower wall-clock.
4. **MCP:** Claude Code and OpenCode support MCP natively; pi does not and needs `pi-mcp-adapter` — which is arguably better (one ~200-token proxy tool vs 10k+ of schemas) but is a third-party package. → Decision: fine for you, since your only near-term MCP needs are Neon/Pinecone and both are optional.
5. **Time-to-first-success:** pi day-one "feels sparse to the point of feeling broken"; Claude Code and OpenCode work out of the box. → Decision: as a beginner, do the setup in §B *before* your first real task, or you will conclude pi is broken when it is merely empty.
6. **Extensibility / owning the harness:** only pi lets you register tools, intercept `tool_call`, rewrite the system prompt, and branch the session tree from ~40 lines of TypeScript, with an SDK and RPC mode for embedding in the Next.js app later. → Decision: this is the actual reason to pick pi, and it is also how `value_company`, the golden-test guard, and the vintage-stamp enforcement get built.

KEY FACTS:
 - Canonical repo moved from badlogic/pi-mono to earendil-works/pi (MIT, 104,792 stars, last push 2026-09-13); npm package is @earendil-works/pi-coding-agent v0.85.1, node >=22.19.0. The legacy @mariozechner/pi-coding-agent scope should NOT be installed.
 - Install: `npm install -g --ignore-scripts @earendil-works/pi-coding-agent` (or `curl -fsSL https://pi.dev/install.sh | sh`). --ignore-scripts is the documented default for supply-chain reasons.
 - Config dirs: global `~/.pi/agent/` (settings.json, auth.json, models.json, sessions/, extensions/, skills/, prompts/, themes/, agents/, AGENTS.md, SYSTEM.md, trust.json, npm/, git/) overridable via PI_CODING_AGENT_DIR; project-level `.pi/` mirrors all of it. Precedence: CLI flags > .pi/settings.json > ~/.pi/agent/settings.json, nested objects merge recursively.
 - OpenRouter is a BUILT-IN provider: env var OPENROUTER_API_KEY, baseUrl https://openrouter.ai/api/v1, supports both anthropic-messages and openai-completions APIs, ships a generated priced model catalog (packages/ai/src/providers/data/openrouter.json). OAuth via `/login openrouter` (PKCE, paste-code fallback for headless). Credential order: --api-key > auth.json > env > models.json.
 - Model switching: `/model` or Ctrl+L; Ctrl+S in the picker saves the startup default; Ctrl+P cycles a scoped list (`enabledModels` / `--models` / `/scoped-models`). models.json is re-read on every `/model` open, with cost.input/output/cacheRead/cacheWrite per million tokens plus tiered pricing.
 - Skills = directory with SKILL.md; frontmatter name (required, <=64 chars) + description (required, <=1024 chars) + optional license, compatibility; optional scripts/, references/, assets/. Progressive disclosure: only descriptions stay in context; full body loads on demand. Explicit trigger `/skill:<name>`. Discovered from ~/.pi/agent/skills, ~/.agents/skills, .pi/skills, .agents/skills, packages, --skill.
 - Extensions = TypeScript default-export factory taking ExtensionAPI. Surface: registerTool (TypeBox params, execute, renderCall/renderResult), registerCommand, registerShortcut, registerFlag, registerProvider, message/entry/markdown renderers; ~40 events including tool_call, input, before_provider_request, session_before_compact; ctx.ui (select/confirm/input/editor/custom/notify/setStatus/setWidget); full session control (fork, newSession, navigateTree, compact). Discovered from ~/.pi/agent/extensions/*.ts|*/index.ts and .pi/extensions/. Extensions run with full system permissions.
 - Prompt templates = Markdown with optional `description` and `argument-hint` frontmatter, filename becomes /command, substitution $1 $@ $ARGUMENTS ${1:-default} ${@:N:L}. Themes = JSON with required unique `name`, `vars`, and all 53 color tokens; built-ins dark and light plus `light/dark` terminal-following.
 - `pi install` sources: npm:<pkg>[@ver], git:github.com/user/repo@ref, https://github.com/..., and local absolute/relative paths; -l writes to project .pi/settings.json. Also pi remove / pi list / pi update --extensions. Package manifest uses a `pi` key in package.json listing extensions/skills/prompts/themes.
 - Sub-agents are NOT built in. Main option: `pi install npm:pi-subagents` (v0.67.0, published 2026-09-10, ~428.8K monthly downloads, MIT, author nicopreme) with scout/researcher/worker/reviewer/oracle/delegate, foreground streaming + detached background runners, and mcp:server-name frontmatter. Alternatives: @tintinweb/pi-subagents, @d3ara1n/pi-subagent, mjakl/pi-subagent. Official example examples/extensions/subagent/ spawns a separate pi process per agent with .md agent definitions in ~/.pi/agent/agents or .pi/agents.
 - Sessions: tree-structured JSONL auto-saved to ~/.pi/agent/sessions/ bucketed by cwd. Flags -c continue, -r resume, --session, --fork, --name, --no-session. Commands /session /name /resume /tree /fork /clone /new /export (HTML or JSONL) /import /share (uploads a private GitHub gist with shareable HTML link).
 - MCP is NOT native — pi.dev lists it among deliberate omissions; tracking issue earendil-works/pi#563. De-facto solution: `pi install npm:pi-mcp-adapter` (nicobailon), auto-detects ~/.config/mcp/mcp.json and .mcp.json, exposes ONE ~200-token proxy tool instead of 10k+ tokens of schemas; a Sept-2026 review cites 197,718 weekly downloads.
 - No built-in sandbox and no permission popups: docs/security.md says built-in tools run with the pi process's permissions and prompt injection is 'expected local-agent risk'. Only built-in gate is project trust (trust.json, defaultProjectTrust ask/always/never, -a/--approve, -na/--no-approve, /trust).
 - macOS-without-Docker sandbox answer is examples/extensions/sandbox/: depends on @anthropic-ai/sandbox-runtime@0.0.26 and uses sandbox-exec on macOS (bubblewrap on Linux), overriding the built-in bash tool. Config merges ~/.pi/agent/extensions/sandbox.json and <cwd>/.pi/sandbox.json with network.allowedDomains/deniedDomains and filesystem.denyRead/allowWrite/denyWrite. Defaults deny-read ~/.ssh ~/.aws ~/.gnupg and deny-write .env/*.pem/*.key. Usage: pi -e ./sandbox, --no-sandbox, /sandbox. docs/containerization.md itself covers only Gondolin (QEMU micro-VM, node>=23.6), Docker, and NVIDIA OpenShell and never mentions macOS.
 - Context files: ~/.pi/agent/AGENTS.md then every parent dir then cwd; CLAUDE.md accepted as an alternative filename; AGENTS.override.md replaces standard files for that dir; .pi/SYSTEM.md > ~/.pi/agent/SYSTEM.md replace the system prompt while APPEND_SYSTEM.md appends; --no-context-files/-nc disables. examples/extensions/claude-rules.ts reads .claude/rules/.
 - Compaction: auto-triggers when contextTokens > contextWindow - reserveTokens (default 16384), keeps keepRecentTokens (default 20000), LLM-summarises the cut region and rebuilds context as summary + recent. Manual /compact [instructions]. THERE IS NO /clear — the equivalents are /new, /fork, /clone, --no-session.
 - Cost transparency: TUI footer shows live token/cache usage, USD cost, context usage and model; /session prints messages/tokens/cost. There is NO /usage command, and a Sept-2026 review flags uneven cost visibility across modes (footer is TUI-only; in -p and --mode json you must parse usage from the event stream).
 - Headless/CI: YES. `pi -p "prompt"` (print), `pi --mode json "prompt"` (line-delimited JSON events, message_update deltas are delta-only with cumulative usage), `pi --mode rpc` (stdin/stdout JSONL), plus the SDK (createAgentSession + SessionManager.inMemory + session.subscribe). A published GitHub Action exists: shaftoe/pi-coding-agent-action@v2 (v2.28.0), inputs github_token/provider/model/token/prompt/pr_number, outputs response/success/cost/duration_seconds/share_url, bundles pi SDK 0.85.1. In non-interactive runs you must pass --approve or set defaultProjectTrust or project .pi/ resources are ignored.
 - 2026 rough edges: sparse/'feels broken' day one until extensions are installed; stdin pipes can hang ~180s without redirection; auto-discovered skills inflate context (48 skills = +9,400 tokens); ~449MB disk footprint with unrequested fd/ripgrep downloads; XDG non-compliance on Linux; repetitive provider warning spam; tool_call guard extensions are advisory and were circumvented by a model reframing a request; no observability or permission layer by design.
 - Measured comparisons: pi baseline context 1,358 tokens vs Claude Code 31,012 (~20x) with per-task cost $0.10/$0.11/$0.31 vs $0.61/$0.77/$1.16 and identical outcomes; vs OpenCode pi scored 21/30 at $1.64 vs 19/30 at $2.25 but was slower at the median (363s vs 281s).
 - Repo ships ~60 example extensions including permission-gate.ts, protected-paths.ts, plan-mode/, subagent/, sandbox/, todo.ts, git-checkpoint.ts, auto-commit-on-exit.ts, dirty-repo-guard.ts, claude-rules.ts, trigger-compact.ts, structured-output.ts (terminate:true, useful for CI), custom-footer.ts, mac-system-theme.ts.
 - Useful env vars: PI_CODING_AGENT_DIR, PI_CODING_AGENT_SESSION_DIR, PI_PACKAGE_DIR, PI_OFFLINE, PI_SKIP_VERSION_CHECK, PI_TELEMETRY, PI_CACHE_RETENTION=long, PI_SHARE_VIEWER_URL. Bash tool calls receive PI_SESSION_ID, PI_SESSION_FILE, PI_PROVIDER, PI_MODEL, PI_REASONING_LEVEL — usable for stamping provenance from inside tool scripts.
